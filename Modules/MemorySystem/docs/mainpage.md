# MemorySystem — аллокаторы FluxEng {#mainpage}

MemorySystem даёт движку память **без конструкторов, без `free` по одному и без утечек**.
Подключение: `#include <MemorySystem/MemorySystem.hpp>`, CMake-цель `engine::MemorySystem`.
Зависимостей, кроме стандартной библиотеки и API ОС, нет.

## ZII — Zero Is Initialization

Объект, все байты которого нули, — корректный объект в «пустом» состоянии:

| Тип | Что значит ноль |
|---|---|
| `Handle{}` / `Entity{}` | «нет объекта» |
| `Vec2{}` | начало координат |
| `std::span<T>{}` | пустой список |
| `MemorySystem::Arena{}` | пустая арена: ничего не выделяет, но и не падает |
| `MemorySystem::ArenaMarker{}` | начало арены |

Отсюда два правила модуля:

1. Аллокаторы **всегда отдают нулевую память** — конструктор не нужен, забыть инициализировать поле нельзя.
2. Типы, которые в ней живут, удовлетворяют концепту MemorySystem::ZeroInitializable
   (trivially copyable + trivially destructible), а смысл нуля описан в их документации.

## Что выбрать

| Задача | Инструмент |
|---|---|
| данные с общим временем жизни (уровень, кадр, запрос) | MemorySystem::Arena |
| временная память внутри функции | MemorySystem::ArenaScope |
| данные, которые живут один тик после создания | MemorySystem::DoubleArena |
| объекты одного типа, создаются и умирают по одному | MemorySystem::Pool |
| `std::pmr`-контейнеры во временной памяти | MemorySystem::ArenaResource |
| свой аллокатор поверх резерва ОС | MemorySystem::VirtualRegion |

## Арена и её инвариант

```
[ занято .............. | нули ........................ | не подтверждено ....... ]
0                  position                        committed                 capacity
```

- **push** — выравнивание и сдвиг `position`. Память уже нулевая: ни `memset`, ни конструктора.
- **pop_to / reset** — зануляют `[marker, position)`. Платим один раз и только за использованное.
- **рост** — виртуальная арена подтверждает страницы шагами (`commit_step`). Новые страницы ОС отдаёт нулевыми.
- **адреса стабильны** — резерв сделан сразу, поэтому указатели в арену никогда не «переезжают».

```cpp
MemorySystem::Arena level = MemorySystem::Arena::reserve(MemorySystem::MiB(256));
LevelHeader* header = level.push<LevelHeader>();              // все поля = 0
auto tiles = level.push_array<std::uint16_t>(64 * 32);        // нулевые тайлы
{
    MemorySystem::ArenaScope scratch(level);                  // временная область
    auto path = level.push_array<std::uint32_t>(4096);
}                                                             // откат + зануление
level.reset();                                                // весь уровень одним вызовом
```

## DoubleArena — та же модель, что у шины событий

Шина EventSystem показывает событие тика N ровно в тике N+1. DoubleArena делает то же для памяти:
всё, что выделено в `current()` в тике N, читается через `previous()` в тике N+1 и освобождается
следующим `swap()`. Хорошо подходит для результатов запросов, путей и списков видимости,
которые передаются событиями по ссылке.

## Pool

Освобождённые блоки хранятся в односвязном списке прямо внутри себя. `free()` зануляет блок,
`allocate()` стирает только указатель списка — выданный объект всегда нулевой.
Блоки лежат в собственной виртуальной арене пула: адреса стабильны.

## Замеры (GCC 14, RelWithDebInfo, x86-64)

| Замер | Время | Против |
|---|---|---|
| Arena::push 32 Б | ~4 нс | malloc 32 Б: ~13 нс |
| кадр: 10 000 объектов + reset | ~36 мкс | new/delete: ~155 мкс |
| Pool: free + allocate | ~4.5 нс | delete + new: ~12.6 нс |
| pmr::vector в арене, 100 000 push_back | ~72 мкс | std::vector: ~76 мкс |
| цена ZII: reset после 1 МиБ | ~20 мкс (≈49 ГиБ/с) | — |

Зануление при откате стоит порядка скорости `memset`. Для арены кадра на несколько мегабайт
это десятки микросекунд — меньше 1% кадра на 60 Гц.

## Ограничения

- Арена и пул не потокобезопасны: одна арена — один поток. Для задач многопоточной шины
  нужны арены на поток (см. локальные буферы писателей в конспекте 2).
- ArenaResource не освобождает память по одному: для контейнеров, которые долго растут,
  заранее вызывайте `reserve()`.
- Детерминированных адресов нет: ОС выбирает, где разместить резерв.
