# InputSystem — ввод без привязки к платформе {#mainpage}

InputSystem — собственные коды ввода движка и всё, что на них строится: состояние за кадр, **действия игры** с переназначением,
**команда ввода за тик** для сети и **запись/воспроизведение**. Окна и GLFW здесь нет, поэтому игровая логика, читающая ввод,
тестируется без дисплея, а платформы (GLFW, SDL, Android, консоли) подключаются через перевод своих событий в `InputEvent`.
Подключение: `#include <InputSystem/InputSystem.hpp>`, цель `engine::InputSystem`. Зависимостей нет.

## Слои

```
 платформа (WindowSystem: GLFW, Headless, …)  ──►  InputEvent  ──►  InputState  ──►  ActionMap  ──►  игра
                                                         │                                  │
                                                         └──► InputLog (запись/реплей)      └──► InputCommand ──► сеть / симуляция
```

| Часть | Что делает |
|---|---|
| InputSystem::Key, MouseButton, GamepadButton, GamepadAxis | собственные **стабильные** коды (клавиши — USB HID); числа не меняются между версиями и платформами |
| InputSystem::InputEvent | сырой ввод от платформы: клавиша, мышь, курсор, колесо, символ, фокус, геймпад |
| InputSystem::InputState | зажато / нажато / отпущено в этом кадре, курсор и его дельта, колесо, текст, геймпады; потеря фокуса отпускает всё |
| InputSystem::ActionMap | «jump», «move_x» ↔ клавиши, кнопки, оси; модификаторы (Ctrl+S), ось из пары клавиш, мёртвая зона; переназначение; **текст настроек** |
| InputSystem::InputCommand | 16 байт без padding и без float: кнопки битами, оси int16; годится как команда NetSystem::Lockstep |
| InputSystem::InputLog | двоичная запись ввода по кадрам с версией и CRC-32; разбор не доверяет данным |

## Почему свои коды

Коды GLFW/SDL — детали библиотеки: они меняются между версиями и платформами, а ваши записи, настройки игроков и сетевые
команды должны жить годами. Свои коды отвязывают игру от платформы: другая платформа лишь переводит свои события в эти.
Значения клавиш — USB HID (`A = 4`, `Space = 44`, `LeftShift = 225`), общий стандарт; золотые тесты фиксируют числа.

## Правила InputState

- `pressed` — клавиша опустилась в этом кадре; автоповтор ОС (`Repeat`) состояние не меняет;
- нажатие и отпускание в одном кадре видны обоими флагами, `down` ложно — быстрый щелчок не теряется;
- потеря фокуса отпускает всё (после Alt-Tab клавиши не «залипают»);
- состояние можно подменить записью: логика не знает, откуда события.

## Правила ActionMap

- Спрашивайте о действиях, не о клавишах; для горячих путей берите `ActionId` один раз (`action_id("jump")`).
- Аналоговое значение (`value`) складывается из привязок и ограничивается −1…+1: клавиши и стик живут в одной оси.
- Ось, считающаяся кнопкой (курок как «тормоз»), срабатывает с порога 0.5, фронты — по двум соседним кадрам.
- Игрок переназначает управление текстом (`to_text` / `from_text`); ошибка разбора называет строку.

## Команда ввода и мультиплеер

`sample_command(actions, state, layout)` превращает действия в числа **на узле, где сидит игрок**; дальше по сети и в симуляции
живут только числа (целые, одинаковые на всех платформах). Раскладка (`CommandLayout`) одинакова у всех и зашита в игру.
Фронт нажатия восстанавливается из двух подряд идущих команд (`button_pressed`).

## Чего здесь нет (сознательно)

Физических позиций клавиш независимо от раскладки (WASD на AZERTY решается переназначением действий), сенсорного ввода и жестов,
вибрации геймпада, ввода через IME, привязок «аккорд из нескольких кнопок». Коды и события рассчитаны на расширение: новые значения только добавляются.
