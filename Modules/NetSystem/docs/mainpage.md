# NetSystem — сеть для детерминированной игры {#mainpage}

NetSystem даёт то, на чём строится мультиплеер «все считают одно и то же»: сериализацию, абстракцию транспорта,
**имитацию сети на виртуальном времени** (задержка, джиттер, потери, дубликаты — воспроизводимо по seed) и
**lockstep-протокол**, где по сети ходят только команды ввода, а состояние каждый узел считает у себя.
Подключение: `#include <NetSystem/NetSystem.hpp>`, цель `engine::NetSystem`. Зависимостей нет (только стандартная библиотека).

## Зачем lockstep

Состояние воксельного мира огромно — гонять его по сети нельзя. Команды ввода малы (8 байт на игрока на тик).
Если симуляция **детерминирована**, одинаковые команды дают одинаковое состояние на всех узлах. Цена — жёсткое требование
к коду симуляции (см. ниже) и ожидание самого медленного канала; выгода — трафик не зависит от размера мира, а
рассинхронизация ловится сверкой хешей.

## Как это устроено

| Часть | Что делает |
|---|---|
| NetSystem::ByteWriter / NetSystem::ByteReader | little-endian, чтение с проверкой границ (враждебный пакет не роняет приём) |
| NetSystem::ITransport | датаграммы «как UDP»; сокеты подключаются этим интерфейсом |
| NetSystem::SimulatedNetwork | сеть в процессе: `advance_to(t)` двигает виртуальное время; тесты быстрые и воспроизводимы |
| NetSystem::Lockstep | команды с задержкой ввода, накопительные подтверждения и повторы, сверка хешей |
| NetSystem::LockstepNode | Lockstep + темп тиков: сам снимает ввод, ждёт чужие команды, вызывает шаг симуляции |

- **Задержка ввода** (`input_delay` тиков): команда, снятая на тике `t`, применяется на `t + input_delay`; пока она летит,
  симуляция не стоит. Сеть быстрее этого запаса — узел не простаивает; медленнее — простаивает (`stalls()`), но не расходится.
- **Ненадёжная сеть.** Потеря, дубликат, перестановка не ломают протокол: узел повторяет то, что сосед ещё не подтвердил.
- **Топологии.** Звезда: сервер-ретранслятор (`relay = true`) знает всех, клиенты — только сервер. Mesh/p2p: все связаны напрямую
  (`relay = false` — каждый шлёт только свои команды; трафик на узел падает почти вдвое).
- **Команда** — структура из целых без padding (`has_unique_object_representations`): одинаковые байты на всех платформах.
  Числа с плавающей точкой в команде запрещены намеренно.

## Требования к детерминированной симуляции

Lockstep честен ровно настолько, насколько детермирована симуляция. Правила, которые уже проверяются тестами песочницы NetSim:

1. Только целочисленная арифметика (или фиксированная точка). Float даёт разные результаты на разных процессорах и компиляторах (FMA, libm).
2. Свой генератор случайных чисел с состоянием внутри симуляции; никаких `rand()`, `std::random_device`, времени, адресов.
3. Порядок обхода — по данным симуляции (плотные массивы ECS), не по `unordered_map` и не по указателям.
4. Параллельные системы пишут результат по номеру куска и сливают по порядку (JobSystem делает это для `parallel_reduce`/`ChunkBuffers`):
   результат не зависит от числа потоков.
5. Ввод и всё, что приходит извне, — только через команды.

## Чего здесь нет (сознательно)

- **Реальных сокетов**: интерфейс готов, реализация UDP — отдельная задача. Имитация сети проверяет протокол раньше и надёжнее.
- **Присоединения посреди игры** (снимок состояния + догон команд) и **зрителей без ввода**.
- **Шифрования и аутентификации**: узлы считаются доверенными (PeerId берётся из транспорта).
- **Предсказания и отката** (rollback): lockstep ждёт; для быстрых экшенов нужен rollback поверх тех же команд.

Подробнее о проверке на практике — песочница `Sandbox/netsim` (несколько узлов, звезда и mesh, разное число потоков, внедрённая рассинхронизация).
