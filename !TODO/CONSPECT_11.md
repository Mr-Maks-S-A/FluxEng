# Конспект 11 — обзор API модулей

Смотрел публичные заголовки новых модулей и швы между ними (где игра или соседний модуль обходит API: дубли, лишние
зависимости, места, где можно сломать детерминизм). Исправлено то, что безопасно и даёт выигрыш сразу; крупное — в
предложениях ниже (нужен выбор направления).

## 1. Что исправлено

| Проблема | Что сделано |
|---|---|
| Конверсия float ↔ Fixed/WorldPos написана заново в игре, `WorldRender` и тестах (`llround(v * 65536)`) | граница с float — одна: `Fixed::from_double`, `WorldPos::from_doubles` / `to_doubles`, `quantize_direction` в `Math`; игра и камера используют их |
| `Character` зависел от конкретного `Terrain`, хотя ему нужно только расстояние до поверхности; тесты строили мир 128 м ради одного шага | интерфейс `Math::SdfField` (`sample`, `gradient` по умолчанию, `Math::raycast`), `Terrain::World` его реализует; `Character` зависит только от Math и ECS; тесты на `PlaneSdf` / `SphereSdf` мгновенные. Это же основа для планет |
| Сортировка сущностей «по id» дублировалась 4 раза (Runes ×2, Character ×2) | `ECS::World::entities_of<T>()` — отсортированный список; пул хранит компоненты в порядке с swap-remove, поэтому детерминированные системы обязаны так обходить |
| Игра вручную склеивала запись/повтор/журнал/итог (≈40 строк в `tick` и `shutdown`) | `Replay::Driver` (`step(live)` / `finish()`) и `Replay::describe`; концепт `Replay::Simulatable`. Игре осталось собрать команды |
| `SpellSim` отдавал наружу изменяемые `terrain()`, `mana()`, `world()`, `rng()`: из игры можно было изменить мир мимо команд, и запись бы не воспроизвелась | наружу только `const`; «двери» — команды в `tick`, `take_dirty_chunks()`, `reload_spells`, `programs()`, `set_grimoire_slot` |
| `ManaField::for_each_chunk` принимал `std::function` | шаблон: без аллокаций и виртуального вызова |
| `Terrain`: перестройка чанка всегда аллоцировала новый буфер; `ground_height(x, z)` принимала два сырых int64 | `mesh_chunk(world, coord, out)` переиспользует память; `ground_height(WorldPos)`; `raycast` и `gradient` теперь из `Math` |
| **Дефект найден тестом на плоскости:** щуп «земля в 15 см» засчитывал опору, и персонаж **зависал над землёй** на ≈10 см (в ландшафтных тестах допуск 0,35 м это скрывал) | прилипание: если земля ближе `Config::snap_distance`, персонаж опускается ровно на зазор |

Итог: 453 / 453 тестов, `check_modules.sh` — все 15 модулей по отдельности. Записи, сделанные до правки `Character`,
не воспроизведутся (физика изменилась) — для пре-альфы это нормально, формат файла не менялся.

## 2. Предложения 1–7 — сделаны (раздел 3); оставшиеся 8–9 — в конце

(Ниже — исходные формулировки, для истории.)

Порядок — по пользе для планов (машины, планеты, сеть).

1. **Фазы тика как список, а не код в `SpellSim::tick`.** Сейчас новый модуль (машины, гравитация тел) требует править
   `Simulation`. Предложение: `TickPipeline` с зарегистрированными фазами `{имя, функция}` в заданном порядке; замеры
   по фазам собираются автоматически (сейчас `PhaseTimes` — шесть жёстких полей), порядок виден в отладке и в документации.
   Это главный шаг к «модули подключаются, а не вписываются».
2. **Эффекты заклинаний как данные.** `Runes::SpellHost` — 8 виртуальных методов, часть из них меняет мир прямо из машины
   рун. Вместо этого руны кладут `Effect{Carve|Raise|Draw, pos, r}` в буфер, а мир применяет его в своей фазе. Плюсы:
   машина рун становится чистой функцией (проще сеть, откат, параллельный запуск многих заклинаний), эффекты сериализуются
   и попадают в трассу; хост сужается до «чувств» (`position`, `target`, `density`) и «кошелька» маны.
3. **Размеры мира — данные, не константы.** `Terrain` зашит на 8×4×8 чанков (`constexpr`), поэтому два мира (измерения,
   планеты) в одном процессе невозможны. Предложение: `WorldLayout` в конструкторе + источник чанков
   (`ChunkSource::load(coord)`), в духе `ManaField`, которое уже безгранично. Заодно убрать наружу сырые Q8.8 (`distance_at`).
4. **Единицы измерения.** `Fixed` означает и метры, и ману, и секунды — перепутать их компилятор не помешает.
   Тонкие обёртки (`Meters`, `Mana`) с теми же операциями стоят недорого, пока кода мало. Не обязательно везде — начать с `Mana`.
5. **Типизированные команды.** `Replay::Command` — универсальные 16 байт (`type, arg, x, y, z`); смысл полей знает только
   игра. Предложение: реестр схем команд (как в `EventSystem`) — файл записи самоописываем, инструменты (просмотр,
   сравнение двух записей, сеть) работают без знания игры.
6. **Коды ошибок вместо текста.** `ParseError`, `GraphError`, `Failure` — три разных формата, сообщения на русском зашиты
   в библиотеку. Предложение: общий `Diagnostic{код, строка|узел, аргументы}`; текст — на стороне UI (и тесты перестают
   зависеть от формулировок).
7. **Имена.** `Terrain::World`, `ManaField::Field`, `ECS::World` — одинаковые «World/Field» в разных пространствах
   имён путают при чтении. Предложение: `Terrain::SdfWorld`, `ManaField::ManaGrid`. Дёшево, пока модулей мало.
8. **Ввод через действия.** Игра 40 раз пишет `in.pressed(GLFW_KEY_…)`; нужна карта «действие → клавиша» в `Core`
   (перепривязка, геймпад, запись ввода как событий). Нужно до редактора рун.
9. **`WorldRender` ↔ `Terrain`/`ManaField`.** Рендер знает конкретные типы. Если добавятся планеты и LOD, лучше принимать
   «источник мешей» и «источник тумана» интерфейсом. Пока не срочно.

Мой выбор на ближайшее: **1 → 2 → 3** (они определяют, как подключаются машины и планеты), 6 и 7 — попутно.

## 3. Выполнено: предложения 1–7

Итог: **471 / 471** тест, `check_modules.sh` — все 16 модулей по отдельности. Новый модуль: `Phases`. Новый инструмент: `ReplayTool`.

### 1. Расписание фаз тика — модуль `Phases`
`Phases::Schedule`: упорядоченный список именованных шагов (`add`, `insert_before/after`, `remove`, `set_enabled`), замеры по фазам
и сумма собираются сами. `SpellSim::tick` теперь только `m_schedule.run()`; шесть фаз — приватные методы, зарегистрированные
в `build_schedule()`. Новый модуль (машины, гравитация тел) подключается так: `sim.schedule().insert_after("movement", "machines", fn)`.
Оверлей игры строит строку фаз из `schedule().times()` — новая фаза появится в нём сама. Тест: фаза машин после «movement» видит
обновлённого персонажа; выключенная фаза «mana» замораживает поле.

### 2. Эффекты заклинаний — данные
`Runes::Effect{Carve|Raise, caster, position, radius}` и `EffectBuffer`. `SpellHost` сузился до «чувств» (позиция, цель,
плотность) и «кошелька» (`draw`, `take_personal`, `give_personal`) — изменений мира в нём больше нет. `SpellSystem::tick` принимает
буфер; `SpellSim` применяет эффекты в фазе `terrain`. Радиус в эффекте уже зажат; трасса считает эффекты (`SpellTrace::effects`).
Машина рун стала чистой функцией от (программа, состояние, чувства): её можно записывать, откатывать, гонять параллельно.

### 3. Форма мира — данные
`Terrain::Layout{chunks_x, chunks_y, chunks_z}` (по умолчанию 8×4×8) вместо `constexpr`-размеров; `ChunkSource` — откуда берутся
данные чанка (`NoiseSource(seed)` — холмы; можно любой: плоскость, файл, сеть). `SdfWorld(seed, layout)` и `SdfWorld(layout, source)`.
Два мира разной формы живут в одном процессе (тест). Рендер (`TerrainView`, `MeshQueue`, туман) и игра берут форму из `world.layout()`.
Сырой Q8.8 спрятан: наружу `distance_at` в метрах (`Fixed`), формат хранения — `raw_distance_at` (мешер, сериализация).

### 4. Единицы: `Math::Mana`
Сильный тип над `Fixed`: `Mana ± Mana`, `Mana · Fixed`, `Mana / Mana → Fixed`, сравнения, литерал `240_mana`. Не компилируется:
`Mana + Fixed`, `Mana · Mana`, ману как радиус. Применён в `ManaField` (`draw`, `inject`, `density`, `Config::base`), `Runes`
(`Tuning`, бюджет, трасса, `SpellHost`), `Character::ManaPool`, `SpellSim::Config`. `Meters` не вводил — пока нет ошибок, которые он бы поймал.

### 5. Типизированные команды и самоописываемая запись
`Replay::CommandRegistry` / `CommandSchema` (имя, смысл и тип полей `arg, x, y, z`). Схемы пишутся в файл (версия 2; версия 1 читается).
`SpellSim`: `MoveCommand`, `JumpCommand`, `CastCommand` с `encode/decode`, `register_commands()`. Старые `move_command(...)` остались
обёртками. Инструменты без знания игры: `Replay::inspect(recording)`, `Replay::diff(a, b)` (сид → команды по порядку → длина → хеши) и
исполняемый `ReplayTool inspect|diff` (проверен в ctest). Пример: `tick 60: cast slot_source=0 aim_x=0.707 aim_y=-0.707 aim_z=0`.

### 6. Коды ошибок: `Runes::Diagnostic`
Один тип вместо `ParseError`, `GraphError` и строк: `Code` (29 кодов) + место (`line` / `node`) + короткая подробность.
`message()` строит текст по умолчанию (русский) в одном месте, `format()` — «строка 3: …» / «узел 7: …» для отчётов библиотеки.
Тесты сравнивают коды, а не формулировки; `parse_fixed` возвращает `Diagnostic` тоже.

### 7. Имена
`Terrain::World` → `Terrain::SdfWorld`, `ManaField::Field` → `ManaField::ManaGrid`.

### Не сделано
Записи, сделанные до правки `Character` из раздела 1, не воспроизведутся (физика изменилась); формат файла читается.

## 4. Выполнено: предложения 8–9 и примеры для каждого модуля

### 8. Ввод через действия — `Core::ActionMap` (`Core/Actions.hpp`)
Игра объявляет действия («прыжок», «каст из окружающей маны») и привязывает к ним клавиши и кнопки мыши; дальше спрашивает про
действия: `down / pressed / released / axis`. Несколько клавиш на действие, перепривязка текстовым файлом игрока (`apply`: ошибка
с номером строки — ничего не применяется), `conflicts`, `serialize` (готовый файл настроек с описаниями), имена привязок
(`W`, `SPACE`, `F5`, `MOUSE_LEFT`). FirstSpell больше не читает ни одной клавиши напрямую: структура `Actions`, флаги `--bindings файл`
и `--print-bindings`. Тесты: 9 в `CoreTests`; пример `Core/examples/01_actions.cpp`.

### 9. Рендер развязан с данными мира
`WorldRender` больше не зависит от `Terrain` и `ManaField`: данные приходят через `SurfaceSource` (сетка одинаковых кубических
чанков + построение сетки чанка; вызывается из потоков JobSystem) и `FogSource` (ячейки и яркость 0…1+). Камера принимает любой
`Math::SdfField`. Готовые источники — отдельная цель `engine::WorldRenderTerrain` (`TerrainSurface`, `ManaFogSource`; логика
«приземного слоя» тумана теперь в адаптере, а не в рендере). Тесты рендера идут на заглушках без Terrain (`WorldRenderTests`),
адаптеры — отдельно (`WorldRenderAdapterTests`). Планеты, LOD и другие миры подключаются новым источником без правки рендера.
