# Terrain — конспект для изучения и переписывания

`src/include/Terrain/{Terrain,Mesher}.hpp`, `src/code/{Terrain,Mesher}.cpp` (~615 строк). Зависит от `Math` (Fixed, SdfField, Hasher, fbm) и `MemorySystem` (Pool чанков).

## 1. Зачем и главная идея

Мир-ландшафт, который **можно копать и насыпать**, хранится как **знаковое поле расстояний (SDF)**, а не как воксели-кубики:
- каждая точка решётки хранит расстояние до поверхности (`< 0` — внутри породы);
- правка — это операция над полем: вырезать шар `d = max(d, −s)`, насыпать `d = min(d, s)`;
- поверхность для рисования строится из поля **marching tetrahedra** на CPU.

Важное разделение: **всё, что влияет на симуляцию, целочисленное** (`Fixed`, `int16`, `int64`) → детерминизм и хеш; `float` есть **только** в сетке для отображения (`ChunkMesh`).

## 3. Как устроено

### 3.1 Данные
- **Чанк 32³ отсчётов**, ячейка 0,5 м (`cell_raw = one_raw/2`). `Chunk{ array<int16,32768> distance; array<uint8,32768> material }` — `ZeroInitializable` (хранится в `MemorySystem::Pool<Chunk>`, тег `Game`).
- `distance` — **Q8.8 в ячейках** (int16), `material` — `Air`/`Rock`. Индекс внутри чанка: `local_index(x,y,z) = (y·32 + z)·32 + x`.
- `Layout{chunks_x, y, z}` (по умолчанию 8×4×8 = 128×64×128 м); размеры мира `(samples − 1)·cell_raw` — последний отсчёт на границе. Чанки хранятся в `vector<Chunk*>`; рядом `m_versions` (версия каждого чанка, старт 1), кэш хешей `m_chunk_hash`/`m_hashed_version`, грязные флаги и список.
- **Форма мира — данные:** `ChunkSource::generate(coord, chunk)`; `NoiseSource(seed)` — холмы из `Math::fbm` (период 24 м, высота 12 + fbm·26 м, расстояние ≈ разность высот). Свой источник = свой мир (плоскость, файл, планета); в одном процессе сколько угодно миров.

### 3.2 `sample(pos)` — расстояние в точке
Точка зажимается в решётку; берутся 8 соседних отсчётов; **трилинейная интерполяция в int64** (масштаб 2⁴⁵ < 2⁶³ при |d| < 2¹⁵), результат переводится Q8.8 → Q16.16 метров (×128). За краем мира — **порода**: глубина растёт с удалением (`−outside − 1 см`, чтобы знак был строго отрицательным), сверху — воздух. Поэтому `SdfWorld` — полноценный `Math::SdfField`: луч (`raycast`), градиент (центральные разности из `SdfField`) и движение персонажа работают без знания о чанках. `raw_distance_at` зажимает индексы — край мира «залипает».

### 3.3 Правки
`edit(center, radius, carve)`:
1. Область = куб сферы + 2 ячейки запаса (там расстояние ещё меняется).
2. Для каждого отсчёта в области: `s = |p − c| − r` (корень целочисленный, `isqrt`), `now = carve ? max(old, −s) : min(old, s)`; если изменилось — пишем `distance` и `material`, расширяем `changed`-границы.
3. Если ничего не изменилось — пустой результат.
4. **Какие чанки затронуты:** сетка чанка `c` читает отсчёты `[c·32 − 1, c·32 + 33]` (слой соседей для ячеек и нормалей), поэтому в `result.chunks` попадают и **соседи**, читающие край; у каждого `++version` и `mark_dirty`.
- `take_dirty()` отдаёт очередь чанков для перестройки сеток (без повторов; сбрасывает флаги).
- `load_chunk` подменяет чанк целиком (загрузка снимка) и помечает грязными **соседей** (27 штук), потому что их сетки читают край.
- `modified(c)` = `version > 1` — менялся ли чанк с генерации (нужно снимкам).

### 3.4 Хеш
`hash()` — `Hasher` по хешам чанков; пересчитываются **только** чанки с изменившейся версией (`m_hashed_version != m_versions`), остальные берутся из кэша. Хешируются байты `distance` и `material` (плотные массивы без padding). Это тот самый хеш `terrain` в `SpellSim::hashes()`.

### 3.5 Мешер (marching tetrahedra)
- Локальная копия отсчётов `[-1, 33]` вокруг чанка (сетка 35³) — нормали и ячейки не ходят к соседним чанкам.
- **Ноль считается «чуть снаружи»** (`0 → 1`): вершина лежит строго внутри ребра, а не в его конце → вершины на общей грани соседних чанков образуются **одними и теми же рёбрами** и совпадают **бит в бит** (швов нет).
- Каждая ячейка-куб режется на **6 тетраэдров** (порядок осей вдоль пути от (0,0,0) к (1,1,1) — одинаков во всех ячейках, поэтому диагонали согласованы между соседями). Для тетраэдра: 1 или 3 внутренних → один треугольник, 2 → четырёхугольник (два треугольника).
- Вершина на ребре создаётся **один раз** (`edge_vertex[точка][код ребра 0..6]`), позиция — линейная интерполяция `t = da/(da−db)`, нормаль — интерполяция градиентов отсчётов, материал — у внутреннего конца ребра.
- Ориентация треугольника: если геометрическая нормаль смотрит против нормали вершин, меняем порядок вершин (лицевая сторона — наружу, против часовой).
- Ячейка принадлежит чанку, где лежит её **минимальный угол**; в последнем чанке мира обход заканчивается на последнем отсчёте.
- Позиции — метры **от угла чанка** (0…16): `float` не теряет точность вдали от начала мира. Мешер читает мир константно → безопасно вызывать из многих потоков (так `WorldRender` строит меши параллельно).
- Бюджет: чанк ≈ 0,8 мс (цель ≤ 2 мс). Transvoxel/LOD отложены.

## 4. Как использовать

```cpp
Terrain::SdfWorld world(/*seed*/ 7);                         // 128×64×128 м, холмы
auto hit = world.raycast(origin, dir, Math::Fixed::from_int(50));        // Math::raycast по SDF
Terrain::EditResult r = world.carve_sphere(hit->position, Math::Fixed::from_int(3));
for (Terrain::ChunkCoord c : world.take_dirty()) {                       // перестроить только изменённые сетки
    Terrain::ChunkMesh mesh = Terrain::mesh_chunk(world, c);             // можно из JobSystem
    /* загрузить mesh в GPU */
}
std::uint64_t h = world.hash();                              // хеш для сравнения прогонов

Terrain::SdfWorld flat(Terrain::Layout{2, 1, 3}, std::make_unique<MySource>());   // свой мир
```
Где это в проекте: `SpellSim::Simulation` владеет `SdfWorld` и применяет заклинания `CARVE`/`RAISE` через `carve_sphere/add_sphere`; `Character` ходит по SDF; `WorldRender` строит из него карту высот и меши; `WorldJournal` сравнивает хеши.

## 5. Что менять осторожно

- **Хеш и формат чанка** — часть golden-эталонов: изменение `NoiseSource`, формата `distance` (Q8.8) или округления правки меняет `terrain`-хеш всех записей.
- **Список «затронутых» чанков при правке** (границы `±1`) должен совпадать с областью, которую читает мешер (`pad = 1`). Измени одно — измени другое, иначе у соседей останутся устаревшие сетки и появятся швы.
- Не вводи `float` в `sample`/`edit`/`hash`: симуляция перестанет быть детерминированной между машинами. В `Mesher.cpp` float допустим, но **сетки на разных платформах могут отличаться** — не клади их в хеш.
- `value == 0 → 1` в `load()` — это защита от дегенеративных вершин; без неё швы между чанками расходятся.
- Трилинейный `sample` рассчитан на `|d| < 2¹⁵` (клэмп `±32767`); большие значения приведут к переполнению int64 при масштабе 2⁴⁵.
- Один и тот же `ChunkSource` обязан быть детерминированным и **потокобезопасным по чтению** (`generate` const).

## 6. Упражнения для переписывания

1. Замени marching tetrahedra на Surface Nets (одна вершина на ячейку): как изменится условие «без швов» и сколько вершин получится?
2. Добавь `carve_box` и `add_capsule` по тому же шаблону `edit` — вынеси формулу расстояния в параметр (`SdfShape`).
3. Сделай LOD: чанк 64 м с шагом ячейки 1 м — какие отсчёты пропустить и как избежать швов между уровнями (Transvoxel)?
4. Реализуй `ChunkSource` из PNG-карты высот и сохрани/загрузи изменённые чанки через `load_chunk`.
5. Измерь `mesh_chunk` в бенчмарке и ускорь: что дороже — `load()` (копия 35³) или обход ячеек?
