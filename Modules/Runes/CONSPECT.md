# Runes — конспект для изучения и переписывания

`src/include/Runes/{Program,Graph,Spells,Wire,Diagnostic,Runes}.hpp` и `src/code/{Program,Graph,Spells,Wire,Diagnostic}.cpp` (~1100 строк кода + заголовки). Зависит от `Math`, `ECSSystem`, `EventSystem`. Мир не знает.

## 1. Зачем и главная идея

Заклинание — **данные, а не код C++**: программа из рун, которую исполняет маленькая **стековая машина**. Мана — **бюджет исполнения**: каждая руна стоит маны, программа останавливается, когда платить нечем, поэтому бесконечный цикл останавливается сам.

Три представления — один байт-код:
```
.rune (текст) ──parse_program──┐
                               ├─► Program (байт-код) ─► SpellSystem (стековая машина)
.rungraph (граф) ──compile─────┘        ▲
          ▲                              │
          └──────── decompile ───────────┘   (если значения не живут на стеке между операторами)
```

Машина — **чистая функция от состояния**: она не меняет мир, а возвращает **эффекты как данные** (`Effect{Carve|Raise, …}`). Хозяин мира применяет их в своей фазе тика. Поэтому её легко записывать, откатывать, параллелить и показывать в трассе.

## 3. Как устроено

### 3.1 Язык
Руны: `PUSH x` `DUP` `DROP` · `ADD` `MUL` · `CASTER` `AIM` `TARGET` (вектор — 3 ячейки) · `MANA_AT` · `JMP_IF метка|номер` `HALT` · `DRAW` `CARVE` `RAISE`. Только `PUSH` и `JMP_IF` имеют операнд. Текст: по руне на строку, метки `loop:`, комментарии `#`, `;`, `//`, регистр не важен. Лимиты: **≤ 256 рун** в программе, стек **64** `Fixed`, **≤ 256 исполненных рун за тик** (продолжение в следующем тике).
- Числа: `parse_fixed("-2.75")` → `Fixed.raw` **без float** (до 5 знаков).
- Вектор на стеке: `x` глубже, `y` ближе, `z` на вершине.
- `parse_program` проверяет: известные руны, число операндов, цели переходов внутри программы, длину, метки.

### 3.2 Исполнение (`SpellSystem::run`)
Заклинание — **сущность ECS** с компонентами `SpellProgram` (`shared_ptr<const Program>` — перезагрузка файла не ломает идущие), `MachineState` (стек, `sp`, `pc`, счётчики, статус), `SpellBudget` (остаток, потрачено, источник маны), `SpellCaster` (маг, прицел). `tick` исполняет все активные заклинания **в порядке id**, закончившиеся удаляет.

Цикл одной руны:
1. `pc ≥ размер` → нормальная остановка (`Halted`).
2. Цена: `rune_cost` (0,05) + для `CARVE/RAISE` ещё `effect_k·r³` (радиус берётся с вершины стека **до оплаты**, зажимается в `[min_radius, max_radius]`).
3. **`pay(cost)`**: превышен бюджет → `OutOfBudget`; `Personal` — `take_personal(caster, cost)`; `Ambient` — с мага берётся `cost / ambient_divisor` (10), а остальное тянется из поля `draw(position, ambient_radius, cost)`. Не хватило → `OutOfMana`, `pc` остаётся на неоплаченной руне.
4. `switch (руна)`; любая ошибка (пустой стек, переполнение, переход за пределы) → `Failed` + `SpellFailedEvent`, **движок не падает**.
- `CARVE/RAISE` ждут `x y z r` (≥ 4 ячейки); кладут `Effect` в буфер. `DRAW` забирает ману из поля, **отдаёт магу** и кладёт полученное на стек. `TARGET` — точка попадания луча из глаз (через `SpellHost::target`, дальность `target_range` 40 м).
- **Трасса** (`SpellTrace`): кольцо последних 64 исполненных рун с ценой — по `pc` редактор подсвечивает узел графа.

### 3.3 `SpellHost` — мир глазами заклинания
Интерфейс: `position`, `target`, `density` (чувства), `draw`, `take_personal`, `give_personal` (кошелёк). Реализует `SpellSim` (мост к `ManaField`, `Terrain`, `Character::ManaPool`). Так `Runes` не зависит ни от ландшафта, ни от поля маны, и тестируется с заглушкой.

### 3.4 Граф и компиляция
`GraphNode{rune, value, inputs[], next, branch, x, y}`. Оператор (`CARVE/RAISE/DRAW/JMP_IF/HALT`) связан цепочкой `next`; значения (`PUSH/ADD/MUL/CASTER/AIM/TARGET/MANA_AT`) — деревом входов. Компилятор:
- проверка выражений: известный узел, оператор не используется как значение, число и **ширина** входов (число ≠ вектор), нет циклов по данным, `DUP/DROP` в графе запрещены;
- обход цепочек очередью; для оператора сначала `emit_expression` входов (в глубину), затем сама руна; `DRAW` дополняется `DROP` (результат в графе не используется);
- `JMP_IF` получает адрес ветки через fixups; безусловный переход — `PUSH 1; JMP_IF цель`; конец цепочки — `HALT`;
- `compile_mapped` возвращает ещё `source[pc]` — какой **узел** породил каждую руну (карта для подсветки).
`Graph::remove` не сдвигает номера входов остальных узлов (слот остаётся отключённым), а нумерация новых узлов зависит только от содержимого графа (нужно повтору правок).
`decompile` восстанавливает граф из байт-кода, **если** значения не живут на стеке между операторами (иначе `BadStackShape`/`StackNotEmpty`).

### 3.5 Стоимость заранее
`estimate_cost(program, tuning)` — верхняя оценка одного прохода (ветки складываются); константы протаскиваются через `PUSH/ADD/MUL`, чтобы знать радиус эффекта; `exact`, если все радиусы константны; `loops` — есть переход назад.

### 3.6 `Wire` — программа как байты
Канонический вид: `u16` число рун + на каждую `u8` руна и `i32` операнд (little-endian). `program_hash` = `Math::content_hash` байтов (имя не входит) → один адрес для записи повтора, сети и `SetProgram`. `decode_program` — **граница доверия**: длина, известные руны, цели переходов, ненулевые операнды у рун без операнда, лишние байты — всё отвергается диагностикой, не падением.

### 3.7 `ProgramLibrary` и диагностика
Каталог `*.rune`/`*.rungraph` → имя файла без расширения = имя заклинания; `load_directory` возвращает отчёт (`файл:строка: сообщение`), программа с ошибкой остаётся прежней. `Diagnostic` несёт **код** (для логики и тестов) и контекст; `message()`/`format()` строят текст — логика не сравнивает строки.

## 4. Как использовать

```cpp
Runes::ProgramLibrary library;
library.add_text("carve", "TARGET\nPUSH 2\nCARVE\nHALT\n");         // или load_directory("spells/")

Runes::SpellSystem spells;                                         // spells.declare(bus) — события в шину
ECS::Entity s = spells.cast(world, mage, library.find("carve"), aim, Runes::ManaSource::Ambient);
Runes::EffectBuffer effects;
spells.tick(world, host, effects);                                 // host — ваш SpellHost
for (const Runes::Effect& e : effects) { /* применить к миру: carve_sphere / add_sphere */ }

auto bytes = Runes::encode_program(*library.find("carve"));        // для сети / записи
std::uint64_t h = Runes::program_hash(*library.find("carve"));
```
Где это в проекте: `SpellSim` (владеет `SpellSystem`, реализует `SpellHost`, применяет эффекты), `RuneEditor` (граф, `compile_mapped`, `estimate_cost`), `Challenge` (эталонные решения как тексты программ), `Net`/`Replay` (программа едет блобом по хешу).

## 5. Что менять осторожно

- **Цены и порядок оплаты** (`Tuning`, `pay`) определяют поведение golden-сценариев — любое изменение требует обновить эталоны.
- **Известная ошибка (утечка маны):** для `Ambient` сначала списывается `cost/N` с мага (`take_personal`), и только потом `draw` из поля; если поле отдало меньше — заклинание проваливается **после** списания личной маны. Правка меняет хеши golden — делай её отдельным коммитом с обновлением эталонов (конспекты 15–16).
- `Effect.radius` — **уже зажатый** радиус; не пересчитывай его при применении.
- Добавляя руну: `enum Rune` (до `Count`), `rune_name`, `has_operand`, `switch` в `run`, `widths_table`/`value_width`/`is_statement` в графе, `decompile`, `estimate_cost`, `Wire` (проверка), редакторские таблицы (`RuneEditor`) — иначе где-то получишь `UnknownRune`.
- Формат `Wire` — часть сети и файлов записи: менять только с версией.
- Лимиты (256 рун, 64 ячейки стека) заданы константами и проверяются в трёх местах (парсер, `decode_program`, компилятор графа) — меняй согласованно.
- Заклинание держит `shared_ptr<const Program>` — **не изменяй** программу «на месте», заменяй целиком (`add_program`).

## 6. Упражнения для переписывания

1. Добавь руны `SUB`, `LT` (сравнение) и `JMP` (безусловный) — пройди весь список из §5 и посмотри, сколько мест пришлось тронуть.
2. Реализуй **функции/подпрограммы** (`CALL`, `RET` с отдельным стеком вызовов) — как изменятся `estimate_cost`, `decompile` и `Wire`?
3. Исправь утечку маны (проверка доступной маны поля **до** списания личной) и обнови golden; опиши, какие сценарии изменились.
4. Напиши оптимизатор констант (сверка `PUSH a; PUSH b; ADD` → `PUSH a+b`) и докажи, что цена программы не растёт.
5. Реализуй `SpellHost` для тестов без `SpellSim` (лог вызовов) и прогони машину на случайных программах (фаззинг `decode_program` + исполнение).
