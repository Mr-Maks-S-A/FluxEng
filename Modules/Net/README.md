# Net — сеть для детерминированной симуляции (lockstep)

Симуляция детерминирована, поэтому по сети ходит не состояние мира, а **ввод**: каждый пир шлёт свои команды на тик
`T + input_delay`, а тик `T` исполняется, когда команды всех пиров на него собраны. Склейка идёт в порядке номеров пиров —
одинаково у всех. Хеши подсистем сверяются, расхождение называется по тику и подсистеме.

Подключение: `#include <Net/Net.hpp>` (или отдельные `Lockstep.hpp`, `Node.hpp`, `Transport.hpp`, `Wire.hpp`), цель `engine::Net` (входит в `engine::Simulation`). Зависит от `Math` и `Replay` (тип `Command`, `StateHashes`).

```cpp
Net::Lockstep net(transport, {.local = my_id, .peers = 2, .seed = world_seed, .config_hash = level_hash, .input_delay = 3});
net.set_blob_reference(SpellSim::blob_reference);   // команда SetProgram ждёт свою программу

// каждый кадр:
net.pump();                                         // принять пакеты, отправить/повторить свои
if (net.needs_input()) net.submit(my_commands);     // свои команды на тик tick() + input_delay
if (net.ready()) {                                  // команды ВСЕХ пиров на tick() есть
    sim.tick(net.advance());                        // одинаково у всех
    net.report_hashes(sim.hashes());                // сверка именованных хешей
}                                                   // не готово — кадр без шага; игра не падает и не «уходит вперёд»
if (auto d = net.desync()) report(d->tick, d->subsystems);   // «разошлись на тике 912: mana»
```

Правки редактора идут тем же путём: программа уходит блобом (`net.submit_blob(Runes::encode_program(p))` → хеш), а в команде
`SpellSim::set_program_command(slot, hash)` — только хеш (16 байт). Команда не исполнится, пока блоб не пришёл и не сошёлся с хешем.

## Что внутри

| Часть | Идея |
|---|---|
| `Wire` (`encode`/`decode`) | пакеты `Hello`, `Inputs`, `BlobChunk`, `BlobAck`, `HashReport` с версией и CRC-32C; `decode` — граница доверия: любая порча или обрезка — отказ с текстом, не падение. Пакет ≤ 1200 байт (один MTU) |
| `Transport` | единственное, что протокол просит у сети: `local_id()`, `send(peer, bytes)` и `receive(out)`. UDP подключается тонкой обёрткой |
| `SimulatedNetwork` | «плохая сеть» в памяти на виртуальном времени (микросекунды) по сиду: задержка, разброс (перестановка), потери, дубликаты, порча бита, свои параметры по направлениям (`set_link`), обрыв на лету. Тесты и примеры воспроизводимы |
| `Lockstep` | задержка ввода, склейка по пирам, подтверждения, повторы, блобы по хешу, сверка хешей, топологии mesh и звезда (`neighbors`, `relay`), `stats()` |
| `Node` | `Lockstep` + темп тиков по часам узла: сам снимает ввод, ждёт чужие команды, шагает симуляцию, рассылает хеши. Для консольных песочниц, серверов и тестов; игра с собственным циклом берёт `Lockstep` |

**Топологии.** По умолчанию — **mesh**: каждый связан с каждым и шлёт только свои команды. **Звезда**: клиентам `neighbors = {0}`,
серверу (он тоже игрок) `relay = true` — он пересылает чужие команды и блобы; хеши сверяются между соседями (клиенты видят сервер, сервер —
всех, поэтому расхождение клиента ловится сервером и самим клиентом). До 16 игроков (`max_peers`); пакет — один MTU при любом их числе.

**Надёжность без отдельных запросов.** Пакет `Inputs` несёт *все* ещё не подтверждённые соседом тики (и подтверждение принятых по каждому игроку): потеря лечится
следующим пакетом, дубликаты и перестановки безвредны. Блоб идёт кусками по 1000 байт с подтверждением и повторами (не больше
`max_blob_chunks_per_pump` кусков на пира за `pump` — большой блоб не заглушает ввод). Знакомство (`Hello`) сверяет число игроков, сид и
`config_hash` (уровень, версия правил): несовпадение — `failure()`, шаги не делаются.

**Свойства, проверенные тестами:** на тике N состояние одинаково при любом качестве сети (идеальная; задержка 3 + разброс 4 + потери 20 % +
дубли + порча — результат тот же); три пира; блоб 2,6 КиБ при потерях 25 %, команда ждёт его; обрыв связи — игра стоит и догоняет после
восстановления; звезда и mesh на 1–16 игроках при потерях 10–30 %; часы узлов с разной скоростью; блоб через сервер звезды;
недетерминированный пир обнаружен на первом тике расхождения с названием подсистемы; фаззинг разбора пакетов.

## Границы

- Пиры считаются **честными**: подмена ввода и «мёртвый» блоб останавливают игру (`stalled_pumps`), но не карают. Исключение пира, таймауты,
  переподключение с досылкой состояния — следующий слой (у состояния уже есть хеши по подсистемам, а у `Replay` — потоковый журнал).
- Хеш содержимого блоба — FNV-1a 64 бита: защита от случайных ошибок, не от злоумышленника.
- `Replay::Command` — 16 байт и без номера игрока: склеенные команды тика идут по порядку игроков. Если каждый игрок подаёт ровно
  столько-то команд на тик, игрок определяется позицией (так сделаны `NetSim` и интеграционный тест ввода). Номер игрока в команде — открытый вопрос.
- В `SpellSim` пока один персонаж: пиры управляют им совместно (пилот ходит и кастует, писарь пишет заклинания — пример `Sandbox/CoopScribe`).
  Несколько персонажей — следующий шаг: идентификатор игрока в команде.

Примеры: `01_two_peers` (минимальный цикл), `02_bad_network_and_desync` (плохая сеть, обнаружение расхождения), `03_star_node` (звезда на `Node`). Тесты: `NetTests`;
бенчмарки: `NetBenchmarks` (кодирование/разбор пакетов, кадр протокола на 2/4/8 пиров, потери, доставка блоба).

## Дополнения (2026-10-13)

- **Номер игрока.** Каждая исполняемая команда несёт `player` — номер пира, приславшего её (проставляет `Lockstep::advance`). Протокол версии 3.
- **`LockstepDriver<Sim>`** (`Net/Driver.hpp`): кадр сетевой игры одним вызовом — `pump`, ввод, `advance`, блоб симуляции и в запись раньше команды,
  `tick`, `report_hashes`; необязательная запись партии (`set_record`) и предел тиков (`set_tick_limit`).
- **`UdpTransport`** (`Net/Udp.hpp`): настоящий UDP по loopback и сети, тот же интерфейс `Transport`, что у `SimulatedNetwork`. POSIX; на Windows — ошибка при `open`.
- **Живость.** `pumps_since_heard(peer)`, `silent_peers(threshold)` — детектор молчания пира (исключать пира или ждать — решает игра).
