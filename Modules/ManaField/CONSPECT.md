# ManaField — конспект для изучения и переписывания

`src/include/ManaField/ManaField.hpp` и `src/code/ManaField.cpp` (~300 строк). Зависит только от `Math`.

## 1. Зачем и главная идея

Мана в мире — не число у мага, а **физическое поле**: скалярная плотность в ячейках 2×2×2 м. Заклинание **забирает** ману из окружения (`draw`) — в поле остаётся «дыра», которая **затягивается**:
- **диффузия** — потоки между соседними ячейками (сумма сохраняется *точно*);
- **релаксация** — возврат к базовому уровню (единственный «источник» маны в мире).

Три свойства, ради которых модуль устроен именно так:
1. **Разреженность и безграничность:** незагруженная ячейка равна базе, поэтому новое поле **не занимает памяти** (шаг пустого поля ≈ 1,5 нс); мир ограничен только `WorldPos` (int64).
2. **Точное сохранение:** диффузия переносит ровно столько, сколько вычитает из соседа — ни одна единица маны не теряется и не рождается (кроме релаксации).
3. **Детерминизм:** весь обход идёт в порядке ключей `std::map`, все вычисления целочисленные, хеш не зависит от истории выделения «пустых» чанков.

## 2. Карта типов

| Тип | Зачем |
|---|---|
| `Config{diffusion, relax, base}` | доля разности, уходящая в соседа за шаг (**≤ 1/6**, иначе неустойчиво — `FLUX_ASSERT`); доля возврата к базе; базовая плотность (40) |
| `CellPos` / `ChunkKey` | индексы ячейки и чанка (int64); `floor_div` — деление к минус бесконечности (отрицательные координаты!) |
| `cell_of(WorldPos)`, `chunk_of(CellPos)`, `local_index` | перевод мировой позиции → ячейка → чанк → индекс в чанке |
| `ManaGrid` | само поле |

Константы: чанк 16³ ячеек (`chunk_cells`), ячейка 2 м (`cell_raw = 2·one_raw`), чанк 32 м = 2×2×2 чанка `Terrain`.

## 3. Как устроено

### 3.1 Хранение
`std::map<ChunkKey, unique_ptr<Chunk>>`, `Chunk{cur[4096], next[4096]}` (двойной буфер для шага). `at(cell)`: нет чанка → `config.base` («виртуальная база»). `ensure(key)` создаёт чанк, заполненный базой — он появляется только при `draw`/`inject` и в шаге как «гало». Чанк **освобождается**, когда все ячейки вернулись к базе (`settled`).

### 3.2 `step()` — диффузия + релаксация
1. Пустое поле → выход сразу.
2. **Гало:** для каждого существующего чанка создаются его 6 соседей по граням (список ключей берётся заранее, поэтому гало гало не создаётся) — они принимают поток; если поток не дошёл, они освободятся.
3. `next = cur` у всех.
4. **Диффузия:** каждая пара соседних ячеек обрабатывается **один раз** — по трём «положительным» направлениям (x+1, y+1, z+1) от ячейки; если сосед в другом чанке — берётся этот чанк (если он есть). `flow = (a − b)·d / one_raw` (int64, усечение к нулю), `a.next −= flow`, `b.next += flow` — **симметрично**, поэтому сумма сохраняется точно, в том числе через границы чанков.
5. **Релаксация:** `delta = (base − cur)·relax/one_raw`; если получился 0 — **±1 единица**, чтобы поле сходилось ровно (иначе дыры «застревали» бы на небольших отклонениях и чанки не освобождались).
6. `cur = next`; чанк, все ячейки которого равны базе, удаляется; `++version`.

Вызывается 10 раз в секунду (в `SpellSim` — каждый 6-й тик при 60 Гц).

### 3.3 `draw(pos, radius, amount)` — забрать ману из шара
1. Область — куб вокруг шара; ячейка «внутри», если **центр** ячейки в шаре (целочисленно: `dx²+dy²+dz² ≤ r²`).
2. `available` = сумма плотностей внутри; `want = min(amount, available)`.
3. Забор **пропорционально плотности**: `part = cell·want/available` (int64) из каждой ячейки.
4. **Остаток** от целочисленного деления (меньше числа ячеек единиц) добирается ещё одним проходом по порядку, пока `taken == want` — возвращается ровно `want`.
5. `++version`. Ячейка не уходит ниже нуля (`part ≤ cell`).
- `inject(pos, amount)` добавляет в ячейку точки.

### 3.4 Хеш и версия
`version()` растёт при любом изменении (рендер пересобирает туман по нему, не сравнивая поле). `hash()` — по ключам и содержимому **не «пустых»** чанков, пересчитывается лениво при смене версии. Пустые (settled) чанки пропускаются — поэтому хеш не зависит от того, были ли гало выделены.

### 3.5 Служебное
`excess_raw()` = Σ(ячейка − база) — инвариант для тестов (диффузия его сохраняет); `for_each_chunk` — доступ рендеру (карта плотности); `allocated_chunks()`.

## 4. Как использовать

```cpp
ManaField::ManaGrid grid;                                    // везде база, ни одного чанка
Math::Mana got = grid.draw(mage_pos, Math::Fixed::from_int(3), Math::Mana::from_int(240));
grid.step();                                                  // 10 раз в секунду
Math::Mana here = grid.density(mage_pos);                     // яркость тумана = плотность / база
std::uint64_t h = grid.hash();                                // для хеша симуляции
```
Где это в проекте: `SpellSim::Simulation` владеет `ManaGrid` (шагает его по `mana_step_period`, `Runes` забирает ману через `draw` для источника «из окружения»); `WorldRender` рисует туман маны по `for_each_chunk`/`version`; хеш `mana` входит в `StateHashes`.

## 5. Что менять осторожно

- **Коэффициент диффузии ≤ 1/6** (по условию устойчивости явной схемы для 6 соседей): больше — поле осциллирует и расходится. Ассерт стоит на конструкторе; не убирай.
- **Порядок обхода** (`std::map`, затем x/z/y в фиксированном порядке) определяет, как складываются потоки при округлении — изменение порядка меняет хеш.
- **Симметрия обмена** (`a −= flow; b += flow`) — основа сохранения; не заменяй на «каждая ячейка считает свой приток» без проверки инварианта.
- `floor_div` обязателен для отрицательных координат: обычное `/` даст неправильный чанк и «двойную» ячейку вокруг нуля.
- Утечка маны при провале каста из окружения живёт **не здесь**, а в `Runes::SpellSystem::run` (мана мага списывается до `draw`, см. конспект 15) — поле честно возвращает меньше, чем просили.
- Поле одно на мир и не потокобезопасно: `step`/`draw` — только из потока симуляции.

## 6. Упражнения для переписывания

1. Замени `std::map` на хеш-таблицу + сортировку ключей перед обходом — получишь тот же хеш? Измерь шаг.
2. Добавь источники (`Source{pos, rate}`), которые подкачивают ману в ячейку каждый шаг, и проверь, что `excess_raw` растёт линейно.
3. Сделай ветер (направленный поток): асимметричная диффузия — какой инвариант перестанет выполняться и что взять вместо `excess_raw` для проверки?
4. Реализуй шаг параллельно через `JobSystem::parallel_for` по чанкам, сохранив побитовое совпадение с последовательным (подсказка: потоки через границы чанков).
5. Ускорь `draw`: считай `available` без повторного обхода (кэш суммы по чанку).
