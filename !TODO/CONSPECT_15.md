# Конспект 15 — правки заклинаний в потоке команд, сеть lockstep и игровой цикл (уровни)

Пункты 1 и 3 из «что делать дальше» (конспект 14): `SetProgram` + сеть и игровой цикл поверх симуляции.
Три новых вещи: **блобы в записи и `SetProgram`** (Replay, Runes, SpellSim), **модуль `Net`**, **модуль `Challenge`** + игры `CoopScribe` и уровни в `RuneCell2`.

```
 редактор ─ compile ─► Program ─ encode ─► байты ─ content_hash ─► хеш ─┐
                                    │ блоб: запись повтора / пакет сети  │ SetProgram{слот, хеш} — 16 байт
                                    ▼                                     ▼
                         Simulation::provide_program            поток команд (Replay / Net::Lockstep)
                                    └────────────── тик: слот ← «#хеш» ─────┘
```

## 1. Правки редактора — команды (и значит, запись и сеть)

- **Replay: блобы.** `Blob{hash, bytes}`, `Recording::blobs`, `Session::add_blob`, `Driver::submit_blob` (в запись + в симуляцию, если у неё есть `provide_blob`),
  тип записи журнала `blob` (5). Блоб с несовпавшим хешем при чтении **отбрасывается** (подмена не пройдёт тихо). Старые файлы читаются; golden-эталоны не менялись.
- **Math: `content_hash`** (FNV-1a с длиной) — один «адрес по содержимому» для записи, сети и программ.
- **Runes: `Wire.hpp`.** `encode_program` (каноничные байты: одной программе — одни байты), `decode_program` (граница доверия: длина, руны, цели переходов,
  нулевые операнды, лишние байты → диагностика), `program_hash`, `program_name_for_hash` (`#…`). Кодирование ≈ 2,4 мкс, разбор ≈ 0,6 мкс на 255 рун.
- **SpellSim: `SetProgramCommand{slot, hash}`.** Нет блоба или неверный слот → команда отклоняется (`rejected_programs`), слот прежний — отказ одинаков у всех.
  `provide_program(bytes)` (лимит различных программ), `has_program`, `provide_blob`, `blob_reference` (для сети). **Уровни поверх сида:** `Config::setup` (шары породы/пустоты),
  `spawn_offset_*`. Хеши симуляции не изменились: golden-эталоны проходят как есть.
- **RuneCell2** теперь ставит граф командой, а не подменой в библиотеке: правки **попадают в `--record`** (раньше в записи редактор был заблокирован), повтор
  воспроизводит их из блобов (хеши совпадают). Подсветка трассы — только если исполнялась именно показанная программа (по хешу).

**Решение: команда несёт хеш, а не граф.** Команда 16 байт и фиксирована; граф не влезет, а дублировать его в каждой команде расточительно. Блоб по хешу даёт: одну копию на запись,
дедупликацию (повтор правки = тот же хеш), проверку целостности, доставку независимо от команд. Цена — порядок: блоб обязан прийти раньше команды (в записи это обеспечивает
порядок журнала, в сети — «ворота» `ready()`).

## 2. Модуль `Net` — lockstep по ненадёжной сети

Детерминированная симуляция → по сети ходит **ввод**, а не состояние. Пир шлёт команды на тик `T + input_delay`; тик исполняется, когда команды **всех** пиров собраны; склейка — в порядке пиров.

| Часть | Идея |
|---|---|
| `Wire` | пакеты `Hello`/`Inputs`/`BlobChunk`/`BlobAck`/`HashReport`, версия, CRC-32C, ≤ 1200 байт. `decode` — граница доверия (фаззинг в тестах) |
| `Transport` + `LoopbackNetwork` | протокол просит у сети два вызова; «плохая сеть» в памяти по сиду: задержка, разброс (перестановка), потери, дубли, порча бита, обрыв на лету |
| `Lockstep` | пакет `Inputs` несёт **все** неподтверждённые тики и подтверждение принятых: потеря лечится следующим пакетом, отдельных запросов нет; блобы кусками по 1000 байт с подтверждением; ворота по блобам (`set_blob_reference`); сверка именованных хешей → `Desync{tick, peer, subsystems}` |

Проверено: на одном и том же тике **одно и то же состояние** при идеальной сети и при задержке 6 + разброс 8 + потери 30 % + дубли 15 % + порча 8 %; три пира; блоб 2,6 КиБ при потерях 25 %
(команда ждёт его); обрыв связи (игра стоит, потом догоняет); недетерминированный пир найден на первом тике с названием подсистемы.
Замеры (Release, эта машина): кодирование пакета ввода (8 тиков × 2 команды) ≈ 1,1 мкс, разбор ≈ 1,3 мкс (≈ 220 МиБ/с), пустые тики ≈ 0,25 мкс; кадр протокола 2 пира ≈ 2 мкс, 4 пира ≈ 10 мкс,
8 пиров ≈ 46 мкс (квадрат: пакет каждому каждый кадр); доставка блоба 1,3 КиБ при потерях 15 % ≈ 6 шагов сети.

**Границы (честно).** Пиры считаются честными: подмена ввода и «мёртвый» блоб останавливают игру (`stalled_pumps`), но не карают; нет таймаутов, исключения пира, переподключения с досылкой состояния;
хеш блоба — FNV (от случайных ошибок, не от злоумышленника). Реального UDP нет — только `Transport`-интерфейс и сеть в памяти. **В `SpellSim` один персонаж**: пиры управляют им совместно
(пилот ходит и кастует, писарь пишет заклинания). Несколько персонажей — следующий шаг (идентификатор игрока в команде; сейчас в 16 байтах места нет — нужно решение: расширить `Command` или кодировать игрока в `type`).

## 3. Игровой цикл: модуль `Challenge`

Симуляция — сцена без цели; уровень добавляет то, что заставляет **рисовать заклинание**:
- `Level` = мир (`SpellSim::Config`: сид + правки поверх сида + появление + слоты) + библиотека стартовых заклинаний + `Goal` (`Reach` / `Carve` / `Raise`) + `Limits` (время, касты, длина программы, траты маны) + `Par` (звёзды).
- `Referee` читает мир (`const Simulation&`), после каждого тика решает исход, замирает после него. Звёзды: ★ победа, ★★ мана в планке, ★★★ и программа не длиннее.
- Кампания (`campaign()`): **Первый шаг** (дойти) → **Шахта** (прицеливание, шар r=3 — 810 из 1000 маны) → **Курган** (предел трат 150 < цены 240: платить из окружения, но поле вокруг конечно — ~320) →
  **Крепость** (кольцевая стена ~5 м: прорубаться по шагам, ≤ 8 кастов).
- **Эталонные решения** (`reference_solution`) — программы + бот, который целится лучом и ждёт ману, как игрок; без собственного состояния. Тесты доказывают: каждый уровень проходим эталоном на ★★★,
  «стоя на месте» проигрывает везде, «просто идти» проигрывает везде, где нужна магия.
- Рельеф уровней строится по сиду (стены стоят по земле, цели — там, куда виден луч), а не «магическими числами».

**Что показали уровни (находки при калибровке).**
1. Мана-поле в сфере r=3 даёт ≈ 320 маны: окружение — не «бесплатная мана», а ограничение, и это интересная механика (на ней стоит «Курган»).
2. `TARGET` берёт попадание луча в рельеф; прицелиться в точку за бугром нельзя — цели ставятся «из линии видимости».
3. Каст из окружения при нехватке поля **списывает ману мага и всё равно проваливается** (`pay`: `take_personal` до `draw`) — утечка маны в `Runes::SpellSystem::run`; отмечено, не исправлено (меняет поведение golden-сценариев).
4. Попытка «взлететь» кастом `RAISE` под ногами не работает: коллизия выталкивает мага вбок/вниз. Подъёмы потребуют ступеней (`RAISE` по лучу) — в кампанию не вошли.

## 4. Игры

- **`CoopScribe`** (консоль, без GPU): пилот и писарь по плохой сети; у каждого свой мир; миры совпадают побитно; `--cheat` — читер ловится на первом тике с названием подсистемы (`terrain characters`).
- **`RuneCell2 --level id [--bot]`**: отметка цели и строка судьи в HUD, бот эталонного решения проходит уровень в настоящей игре; прохождение «Крепости» записывается и воспроизводится (хеши совпали).
