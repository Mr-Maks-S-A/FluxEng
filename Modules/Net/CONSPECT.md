# Net — конспект для изучения и переписывания

`src/include/Net/{Net,Lockstep,Node,Transport,Wire}.hpp`, `src/code/{Lockstep,Node,Transport,Wire}.cpp` (~1000 строк). Зависит от `Math` и `Replay` (`Command`, `StateHashes`). Реального UDP нет — только интерфейс `Transport` и сеть в памяти. Модуль объединил два прежних: `Net` (протокол для `Replay::Command`: блобы, знакомство, именованные хеши) и `NetSystem` (топологии звезда/mesh, часы узла, сеть в микросекундах).

## 1. Зачем и главная идея

Симуляция детерминирована → по сети идёт **ввод, а не состояние мира** (lockstep). Каждый пир:
- шлёт свои команды на тик `T + input_delay`;
- исполняет тик `T`, только когда команды **всех** пиров на него собраны; склейка идёт в порядке номеров пиров — одинаково у всех;
- сверяет **именованные хеши подсистем**; расхождение называется по тику и подсистеме.

Сеть ненадёжна (потери, задержки, перестановки, дубли, порча) — протокол строится так, чтобы это не требовало отдельных запросов: **любой следующий пакет лечит потерю предыдущих**.

## 3. Как устроено

### 3.1 Пакеты (`Wire`)
`Packet{from, variant<Hello, Inputs, BlobChunk, BlobAck, HashReport>}`; версия протокола, CRC-32C; `decode` — **граница доверия**: любая порча/обрезка → `unexpected(текст)`, не падение; пакет ≤ 1200 байт (один MTU без фрагментации). Фаззинг в тестах.
- `Hello{peer_count, seed, config_hash, knows_you}` — знакомство: сверяет число игроков, сид мира, хеш настройки (уровень + версия правил). `knows_you=false` ⇒ получатель обязан ответить, чтобы знакомство не зависло от потери пакета.
- `Inputs{have[], players[{player, ticks[]}]}` — **все ещё не подтверждённые получателем** тики отправителя (свои и, при ретрансляции, чужие; до бюджета `1200 − 64`, не больше `max_window` тиков игрока) + подтверждение «у меня тики игрока `j` `[0, have[j])`» по каждому игроку.
- `BlobChunk{hash, total, offset, data}` / `BlobAck{hash}` — блобы кусками по 1000 байт.
- `HashReport{tick, hashes}` — хеши подсистем после тика.

### 3.2 `Lockstep` — цикл кадра
```
pump()                 принять пакеты, отправить/повторить свои
needs_input()?  →  submit(commands)     команды на тик tick() + input_delay
ready()?        →  sim.tick(advance())  команды ВСЕХ пиров на tick() есть (и все нужные блобы)
                   report_hashes(sim.hashes())
desync()?       →  разошлись на тике N: подсистемы …
```
Ключевые поля: `m_tick` (исполняемый), `m_local_next` (первый ещё не поданный свой тик), `m_inputs[пир][тик]`, `m_have[игрок]` (тики `[0, have)` есть подряд), `m_peer_have[пир][игрок]` (что у пира есть — по его подтверждениям), `m_neighbors` (с кем обмен напрямую).
- **Старт:** первые `input_delay` тиков **пусты у всех** (никто ещё ничего не мог подать) — иначе игра не стартует. Поэтому `m_have`/`m_peer_have` начинаются с `input_delay`.
- `submit` кладёт команды (≤ 16) на `m_local_next`, сдвигает `m_have[local]`. `ready()` требует: связь есть, у **каждого** пира есть запись на `m_tick` и (если задан `blob_reference`) все блобы, на которые ссылаются команды этого тика. `advance()` склеивает по возрастанию номера пира, ничего не стирает: исполненные тики убирает `pump`, а **свои (и пересылаемые) держит** до подтверждения всеми соседями.
- `pump`: принимает датаграммы (чужие/битые/свои — `bad_packets`), стирает тики игроков ниже `floor = min(m_tick, подтверждения соседей)` (для чужих игроков — только при `relay`), шлёт `Hello` соседям (при отсутствии связи — каждые `resend_interval` pump'ов, потом раз в 32 — дёшево лечит потерю), затем `Inputs` каждому соседу (когда есть что слать, изменились подтверждения или подошёл период повтора) и куски блобов. Если не готов — `stalled_pumps++`.
- `Inputs` на приёме: `m_peer_have[от кого][j]` растёт (не выше того, что есть у нас); принимаются тики любых игроков кроме себя в окне `[have, m_tick + 512)`; затем `have` сдвигается по непрерывному префиксу. Дубликаты и перестановки безвредны (`try_emplace`); две разные команды на один тик — `input_conflicts`.

### 3.2а Топологии
Mesh (по умолчанию): `neighbors` пуст — все остальные; каждый шлёт только **свои** команды. Звезда: клиенту `neighbors = {0}`, серверу `relay = true`: сервер добавляет в пакет клиенту чужие тики (с отдельным подтверждением по каждому игроку) и пересылает полученные блобы остальным соседям (`make_outgoing(..., except = от кого)`). Знакомство и хеши — только между соседями. Связь по `connected()` — со всеми соседями.

### 3.3 Блобы
`submit_blob(bytes)` → `content_hash`; сохраняется локально и ставится в очередь отправки каждому соседу. `send_blobs`: не более `max_blob_chunks_per_pump` (2) кусков на пира за pump, чтобы блоб не заглушил ввод; конец → снова с начала, пока не придёт `BlobAck`. Приём: `Partial{total, data, offsets, received}` (до 16 частичных); собрав все байты, **сверяет хеш**; не сошёлся — отбрасывает (`blobs_rejected`), отправитель повторит. Уже имеющийся блоб подтверждается сразу (потерялось подтверждение).
`set_blob_reference(fn)`: функция «команда → хеш блоба, который ей нужен» (`SpellSim::blob_reference`) — **ворота** `ready()`: команда `SetProgram` не исполнится, пока блоб не пришёл и не сошёлся.

### 3.4 Сверка состояния
`report_hashes` запоминает свои хеши тика `m_tick − 1` (кольцо 256), шлёт `HashReport`; пришедшие раньше своих хешей откладываются; `compare` вызывает `StateHashes::differing` и **запоминает только первое расхождение** (`Desync{tick, peer, subsystems}`) — дальше всё разойдётся.

### 3.5 `SimulatedNetwork` — плохая сеть в памяти
Виртуальное время (`advance_to`, `advance_by`, мкс) и собственный PCG32 по сиду: `latency_us`, `jitter_us` (перестановка), `loss`, `duplicate`, `corrupt` (порча одного бита копии — CRC должна поймать); `set_link(from, to, …)` — свои параметры направления, `set_default_link` меняет линию на лету (обрыв связи). Случайные числа берутся в фиксированном порядке независимо от исхода. Воспроизводимо: те же сид и вызовы — те же потери.

### 3.6 `Node` — темп тиков
`update(now_us)`: `pump`; `due = now × clock_scale / tick_interval`; пока `needs_input` — снимает ввод (`SampleFn`); пока `tick < due` и `ready` (не больше `max_catchup` за вызов) — шагает (`StepFn`) и раз в `hash_interval` тиков рассылает хеши (`HashFn`). Простой считается, только когда связь уже есть. Быстрый узел ждёт медленного: отрыв не больше `input_delay + 1`.

## 4. Как использовать

```cpp
Net::SimulatedNetwork net_sim(/*seed*/ 7, {.latency_us = 3000, .loss = 0.2});
net_sim.add_endpoint(), net_sim.add_endpoint();
Net::Lockstep net(net_sim.endpoint(my_id), {.local = my_id, .peers = 2, .seed = world_seed, .config_hash = level_hash, .input_delay = 3});
net.set_blob_reference(SpellSim::blob_reference);

// каждый кадр:
net_sim.advance_by(1000);             // только в тестах: реальная сеть идёт сама
net.pump();
if (net.needs_input()) net.submit(my_commands);
if (net.ready()) {
    auto cmds = net.advance();
    sim.tick(cmds);
    net.report_hashes(sim.hashes());
}
if (auto d = net.desync()) report(d->tick, d->subsystems);
const std::uint64_t h = net.submit_blob(Runes::encode_program(p));   // правка редактора; затем команда set_program_command(slot, h)
```
Где это в проекте: `Sandbox/CoopScribe` (пилот и писарь по плохой сети, читер ловится на первом тике), интеграционные тесты `Integration.cpu: …net_spellsim`. Рядом: `Replay::Command` — единица обмена; `Replay` и `Net` вместе дают «записать сетевую партию» (пока вручную).

Без своего цикла: `Net::Node node(transport, {.lockstep = {...}, .tick_interval_us = 33'333}, sample, step, hashes);` и `node.update(now_us)` (пример `03_star_node`).

## 5. Что менять осторожно

- **Пиры считаются честными:** подмена ввода и «мёртвый» блоб останавливают игру (`stalled_pumps`), но не карают. Нет таймаутов, исключения пира, переподключения с досылкой состояния.
- **Хеш блоба — FNV** (от случайных ошибок, не от злоумышленника).
- **Инварианты старта:** `input_delay ≥ 1` (`FLUX_ASSERT`), первые `input_delay` тиков пусты у всех. Измени одно — игра не стартует или рассинхронизируется.
- **Свои тики держатся до подтверждения всеми соседями** (иначе нечем лечить потери); освобождение — по `floor` в `pump`.
- Окно приёма ввода `512` тиков и бюджет пакета `1200 − 64` — связаны с `max_packet_size`; при увеличении команд на тик пересчитай бюджет.
- `Hello` повторяется и после соединения — это не лишнее: оно лечит потерю подтверждения знакомства.
- **Номер игрока = номер пира.** `Lockstep::advance` проставляет `Command::player` из номера пира-отправителя (чужую команду за свою не выдать), `SpellSim` с `Config::player_count > 1` ведёт по магу на игрока. «Писарь правит гримуар пилота» теперь явно: `set_program_command(slot, hash, target)`.
- **Живость.** `pumps_since_heard(peer)` и `silent_peers(threshold)` — только детектор молчания; исключение пира из партии должно быть общим решением всех (иначе миры расходятся), это слой выше.
- **Настоящая сеть.** `UdpTransport` (POSIX, IPv4, неблокирующий сокет) — тот же `Transport`; от неизвестного адреса датаграмма отбрасывается. На Windows `open` возвращает ошибку.
- **Цикл кадра.** `LockstepDriver<Sim>` (`Net/Driver.hpp`): pump → ввод → advance → блобы → запись → tick → хеши в один вызов.
- Сложность кадра ~ квадрат числа пиров в mesh (пакет каждому соседу): 2 пира ≈ 2 мкс, 8 пиров ≈ 46 мкс; звезда даёт серверу линейное число соседей, клиентам — одного.
- Номера игрока в команде нет: порядок команд в тике — порядок игроков, поэтому там, где игрок должен быть известен, каждый подаёт фиксированное число команд на тик (`NetSim`, `test_input_lockstep`).
