# Sandbox — объединяющий проект FluxEng

Игры на всех модулях движка: Core, EventSystem, ECSSystem, MemorySystem, JobSystem,
RendererSystem, WindowSystem. Цель — увидеть API модулей в настоящем игровом коде, понять, чего им не хватает,
и измерить, сколько они стоят.

| Цель | Что это | Что показывает |
|---|---|---|
| `engine::Core` (Modules/Core) | слой приложения: окно, рендер, шина, фиксированный тик, пауза/скорость, ввод → события | как модули склеиваются в игровой цикл |
| `FallingSand` | песок, вода, камень, дерево, огонь | массовые SoA-события, сетка в арене (ZII), список изменений в памяти тика, вспышки — сущности ECS |
| `Colony` | упрощённый RimWorld: колонисты, ресурсы, склад, хроника | колонисты и ресурсы в ECS, ссылки `Entity` с поколением в событиях, владельцы компонентов, карта в арене |
| `Ecosystem` | трава, зайцы, лисы: популяции колеблются | рождения и смерти в ECS, устаревшие ссылки отсекает `world.valid()`, интерполяция между тиками |
| `Swarm` | стая из 50 000+ агентов, лезвия, аттракторы | стенд производительности: сетка в памяти тика, плотные пулы ECS, массовые события, замеры каждой системы; Steering и Movement — параллельно |
| `Voxel` | примитивный клон Minecraft: бесконечный мир из чанков, ломать и ставить блоки | **3D-разведка**: чанки в `Pool` (ZII), генерация и сетки чанков через JobSystem, правки блоков событиями, свой 3D-рендер; всё, чего нет в модулях, помечено `[в модуль]` |
| `Siege` | оборона замка: волны врагов, башни, лабиринт, экономика | **все модули сразу**: ECS + события SoA + память тика + JobSystem (5 параллельных систем, события кусков через дорожки шины `writer.lanes()` — без мьютексов, SoA); одинаковый результат при любом `--threads` |
| `RuneCell` | заклинание как живая клетка: руны-атомы с валентностью, мембрана, обмен маны, деление, голем | химия + биология → магия: молекулы и кольца из рун (ECS, связи — ссылки с поколением), мягкая мембрана и тысячи частиц маны на JobSystem, частицы в `Pool`; только Renderer2D |
| `WorldJournal` | эксперимент: мир как «сид + журнал правок» | сохранение через `EventLog` (журнал правок и снимок изменённых чанков), загрузка из сида, восстановление после повреждений файла; сравнение размеров и скорости с полным дампом. Консольный |
| `FirstSpell` | пре-альфа «Первое заклинание»: персонаж на SDF-ландшафте кастует заклинание из файла, туман маны редеет, земля вырезается или поднимается | **игровое ядро в модулях**: `Math` (Fixed), `Terrain` (SDF, меши), `ManaField`, `Runes` (стековая машина, заклинания — сущности ECS), `Character`, `SpellSim` (порядок тика), `Replay` (запись и повтор с хешами), `WorldRender`; в игре — только ввод, камера и HUD. Подробно — `!TODO/CONSPECT_10.md` |
| `RuneCell2` | заклинание-граф: вид сверху на SDF-мир, поле маны тепловым слоем и **визуальный редактор графа рун** (узлы-круги, провода, undo/redo, живая диагностика и цена, подсветка исполнившихся узлов), автосохранение редактора в журнал с избыточностью | **почти вся логика в модулях**: `RuneEditor` (модель, жесты, диагностика, автосохранение, отрисовка), `Runes` (`compile_mapped`, `estimate_cost`), `WorldRender::HeightMap`, `SpellSim`, `Replay`, `EventLog`, `Core::ActionMap`; в игре — склейка и сценарий `--autoplay` с 13 проверками. Подробно — `!TODO/CONSPECT_14.md` |
| `ModuleProof` | игра-проверка: **все 20 модулей движка** в одном живом приложении, чек-лист на экране и в консоли | линкуется с зонтичной `engine::FluxEng`; по одной проверке на тик: Math (CRC-эталон), MemorySystem (арена тика, пул), JobSystem (параллельная сумма = одна нить), Phases, EventSystem, ECSSystem, EventLog (порча блока → восстановление), Replay, Net (2 пира, потери 20 %), ManaField, Terrain, Runes, Character, SpellSim (детерминизм), Challenge (эталон проходит уровень), RuneEditor, WindowSystem (поддельный ввод), RendererSystem, WorldRender, Core. На экране — карта высот (WorldRender) и граф (RuneEditor + View). Не собирается или падает с названием модуля, если тот сломан |
| `CoopScribe` | «пилот и писарь»: два игрока проходят уровень **вместе по плохой сети** (задержка, потери, дубли, порча), консольная | `Net` (lockstep, блобы по хешу, сверка именованных хешей) + `Challenge` (уровень, судья, эталонное решение) + `SpellSim` (`SetProgram` в потоке команд): пилот ходит и кастует, писарь пишет заклинание — программа едет блобом, в команде только хеш. У каждого свой мир, по сети идёт лишь ввод; в конце миры совпадают побитно. `--cheat` — писарь «подправляет» свой мир мимо сети: расхождение находится на первом тике с названием подсистемы. Подробно — `!TODO/CONSPECT_15.md` |
| `CardDuel` | 3D-карточная дуэль в духе Hearthstone: вы против ИИ | **все модули и сторонние библиотеки**: Renderer3D (стол, карты, свет снарядов, прозрачный щит), лица карт — Renderer2D с текстом (stb_truetype) в Framebuffer, рисунки — шум stb_perlin; выбор карты лучом Camera3D; правила (Rules) → журнал `duel.outcome` → сцена ECS с паузами показа; ИИ — сотни случайных продолжений хода на JobSystem в аренах потоков; хроника — spdlog |

Все игры устроены одинаково: **модули-структуры** (свои порты, данные, `declare()` и `tick()`),
общий `ECS::World` в классе игры и **один владелец структуры мира** — создавать и уничтожать
сущности может только один модуль (Life, World, Population, Lifecycle), остальные меняют лишь значения
компонентов. Так обход выборок остаётся безопасным — и параллельные системы могут читать мир без блокировок.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
build/bin/FallingSand
build/bin/Colony
build/bin/Ecosystem

build/bin/Voxel                                          # 3D: мышь, WASD, Space, F — полёт
build/bin/Voxel --autopilot --ticks 1800 --threads 0     # подгрузка мира без ввода: сравнить с --threads N
build/bin/Siege                                          # оборона замка с волны 0
build/bin/Siege --wave 18 --cap 100000 --ticks 900 --no-draw --threads 0   # нагрузка: всё в главном потоке
build/bin/Siege --wave 18 --cap 100000 --ticks 900 --no-draw              # то же параллельно: сумма та же
build/bin/CardDuel                                       # вы против ИИ
build/bin/Voxel --backend vulkan                         # любая игра — на Vulkan
build/bin/RuneCell                                       # магия-клетка; --autoplay — лаборант играет сам
build/bin/FirstSpell                                     # пре-альфа: WASD, мышь, 1–3, ЛКМ/ПКМ (см. шапку first_spell/main.cpp)

build/bin/FirstSpell --replay run.rec                    # повтор записи: хеши ландшафта, маны и ECS на последнем тике
build/bin/RuneCell2                                      # Tab — редактор рун; ЛКМ/ПКМ — каст; см. шапку rune_cell2/main.cpp
build/bin/RuneCell2 --autoplay --ticks 300               # сценарий с проверками: граф строится жестами, выстрел, undo/redo, порча автосохранения
build/bin/RuneCell2 --autoplay --editor --ticks 80 --screenshot rc2.png   # снимок редактора с подсветкой исполнения
build/bin/RuneCell2 --level fort                         # уровень кампании (walk | mine | mound | fort): отметка цели, пределы, звёзды; свой граф — в слот 2

build/bin/RuneCell2 --level mound --bot --record m.rec   # правки заклинаний пишутся в запись командами SetProgram (блобы в файле); --replay m.rec — повтор
build/bin/ModuleProof --ticks 60 --screenshot proof.png  # игра-проверка всех модулей; последняя строка «ModuleProof: OK»
build/bin/CoopScribe --level mound                       # пилот и писарь по плохой сети (консоль): миры совпали побитно
build/bin/CoopScribe --level fort --loss 300 --latency 6 --jitter 8 --delay 5   # ужасная сеть: результат тот же, кадров больше
build/bin/CoopScribe --level mound --cheat               # читер: расхождение найдено и названо по подсистеме
build/bin/FirstSpell --print-bindings                    # привязки клавиш (формат файла); свои — `--bindings файл`
build/bin/WorldJournal                                   # эксперимент: мир = сид + журнал правок (EventLog), снимки, повреждения файла

build/bin/Colony --ticks 375                             # ровно 375 тиков: детерминированный прогон
ctest --test-dir build -L sandbox                        # smoke-тесты всех игр

```

`--backend gl|vulkan` (общий для всех игр) — графический API; `--validation` — слои валидации Vulkan.
Кадры обоих бэкендов совпадают (проверяют тесты), контрольные суммы игр — тоже.

`--threads N` (общий для всех игр, разбирает Core) — число фоновых потоков `app.jobs()`;
по умолчанию ядра − 1, `0` — всё в главном потоке. Swarm и Siege печатают в конце
**контрольную сумму мира**: при любом `N` она одна и та же.

На старте каждая игра печатает граф событий и пишет `<Имя>_events.dot`
(`dot -Tsvg Colony_events.dot -o colony.svg`). По F1 и при выходе — граф, порядок модулей,
предупреждения и статистика каналов.

## Управление

Общее: **Space** — пауза, **= / -** — скорость x1…x8, **WASD / стрелки** — камера,
**колесо** — зум к курсору, **F1** — отчёт по шине, **Esc** — выход.
Столбики слева внизу — активность каналов шины в текущем тике (лог-шкала), красная шапка —
были отброшенные по бюджету события. Справа сверху — пауза или скорость.

- **FallingSand:** ЛКМ — рисовать, ПКМ — стирать, **1–5** — материал, **[ / ]** — размер кисти.
- **Colony:** ЛКМ — посадить дерево, ПКМ — положить камень, **J** — линии заданий.
  Полосы слева сверху — брёвна и камень на складе (засечка каждые 10).
- **Ecosystem:** ЛКМ — выпустить 10 зайцев, ПКМ — выпустить 3 лис. Справа внизу — график численности
  (светлая линия — зайцы, оранжевая — лисы). Каждые 300 тиков Census печатает сводку в консоль;
  `stale hunts` в заголовке — охоты, отброшенные проверкой поколения. В конце — сводка популяций.
- **Swarm:** **[ / ]** — вдвое меньше / больше агентов (1 000…1 000 000), ЛКМ — притягивать к курсору,
  ПКМ — отталкивать. Справа внизу — столбики времени систем (засечка = 1 мс): grid, steering, movement,
  hazards, population, render. Каждые 300 тиков и в конце — отчёт: мс на тик, нс на агента, доля
  бюджета тика, память тика, слоты ECS. **T** — параллельные системы ↔ главный поток.
- **Voxel:** мышь — обзор (**Tab** — отпустить/захватить курсор), **WASD** — ходьба, **Space** — прыжок,
  **F** — полёт (Space/Shift — вверх/вниз), ЛКМ — сломать блок, ПКМ — поставить, **1–8** — блок,
  **P** — пауза (Space занят прыжком: `AppConfig::pause_key`). `--radius N` — дальность в чанках,
  `--autopilot` — полёт по прямой с копанием (замер без ввода). В конце — сводка: чанки, сетки, память,
  мс по системам, контрольная сумма мира.
- **Siege:** строитель ставит башни сам (**B** — выключить/включить), ЛКМ — лучник, ПКМ — мортира
  на клетке под курсором (если хватает золота и путь к замку не перекрывается), **T** — параллельные
  системы ↔ главный поток, **F** — показать поле потоков. Полоса слева сверху — целостность замка.
  Справа внизу — столбики систем (засечка = 2 мс), параллельные — в белой рамке. Каждые 300 тиков —
  строка состояния, в конце — сводка (волна, башни, выстрелы, попадания, убийства, мс по системам,
  контрольная сумма). Аргументы: `--wave N` — начать с волны N, `--cap N` — предел врагов, `--no-draw`.
- **RuneCell2:** WASD, Space, ЛКМ/ПКМ — каст в точку под курсором (личная/окружающая мана), 1–3 слот, Tab — редактор: перетащить узел, потянуть ребро от порта (занятый вход — поднять и перенести), рамка, ПКМ — сдвиг, колесо — масштаб (над PUSH — значение), палитра сверху, Del/X, Ctrl+Z/Y, L раскладка, F вписать, E вход, Enter выстрел, F5 сохранить.
- **FirstSpell:** WASD, Space, мышь; 1–3 — слот гримуара; ЛКМ — каст из личного запаса, ПКМ — из окружающей маны; C — свободная камера (Q/E, Shift); F2 каркас, F3 рамки чанков, F4 срез поля маны, F5 перечитать `*.rune`, F6 трасса заклинания, Tab — отпустить мышь.
- **RuneCell:** 1–5 — руна (Огонь, Вода, Земля, Воздух, Свет), ЛКМ в клетке — посадить, ПКМ с руны на руну —
  связь (повторно — двойная, тройная), щелчок ПКМ по руне — ослабить её самую слабую связь, X — удалить руну,
  Space — запустить клетку под курсором в голема, N — новая клетка, A — автоигра. Справа — формула клетки
  («Ig₂Ve₂ · Te₆Ve₆◯»), урон, лечение, скорость, усиление; хроника реакций и делений.
- **CardDuel:** ЛКМ по карте в руке — сыграть (если нужна цель — ЛКМ по цели, тянется стрела), ЛКМ по своему
  существу — атаковать (провокация закрывает остальных), ПКМ — отмена, кнопка справа или **E** — конец хода,
  **T** — автоигра за вас, **R** — новая партия, **P** — пауза (Space свободен). Под курсором существо показывается
  крупно слева. Зелёная подсветка — что можно сыграть или кем атаковать, красная — допустимые цели.
  Аргументы: `--seed N`, `--autoplay`, `--fast`, `--reveal` (карты ИИ открыты), `--rollouts N` (сила ИИ), `--input-bot`.

## Как написать новую игру

Игра — это `Core::Game` и одна строка в `main()`. Модули игры удобно делать структурами
(как в Ecosystem): свои порты, свои данные, `declare()` с контрактом и `tick()`, куда чужие
данные приходят как `const&`.

```cpp
#include <Core/Core.hpp>

struct Pinged { std::uint32_t id = 0;
    static constexpr std::string_view event_name = "demo.pinged";
    using fields = EventSystem::Fields<EventSystem::Field<"id", &Pinged::id>>; };

struct Pinger {
    EventSystem::EventWriter<Pinged> out;
    void declare(EventSystem::EventBus& bus) { out = bus.writer<Pinged>(bus.declare_module("Pinger").produces<Pinged>()); }
    void tick(EventSystem::Tick now) { out.emit({.id = static_cast<std::uint32_t>(now)}); }
};

class Demo final : public Core::Game {
    Pinger pinger;
    glm::vec2 world_size() const override { return {640, 360}; }
    void setup(Core::App& app) override { pinger.declare(app.bus()); }
    void tick(Core::App& app) override { pinger.tick(app.tick()); }
    void render(Core::App&, RendererSystem::Renderer2D&) override {}
};

int main(int argc, char** argv) { return Core::run<Demo>({.title = "Demo"}, argc, argv); }
```

Добавить цель — одна строка в `foreach(game IN ITEMS ...)` в `Sandbox/CMakeLists.txt` и папка
`<snake_case>/main.cpp`.

## Что нужно дорабатывать (найдено в процессе)

### EventSystem

1. **Нужен второй домен времени.** Ввод доставляется только в тиках симуляции: на паузе
   клики копятся и приходят пачкой после снятия паузы. UI и ввод нужна доставка «на кадр» —
   отдельная шина кадра или политика `Delivery::Frame`.
2. **Нет отложенных событий (`Scheduled`).** Отрастание деревьев в Colony и «молния»
   в FallingSand — ручные очереди по номеру тика.
3. **Нет слияния (`Coalesced`).** FallingSand сам ведёт dirty-флаги, чтобы клетка попадала
   в `cell_changed` не больше раза за тик.
4. **`module_order()` плохо показывает циклы.** Законный цикл World ↔ Jobs ↔ Colonists делает
   «циклическими» и всех, кто ниже (Economy, Chronicle). Нужна конденсация сильно связных
   компонент (Tarjan): цикл — один узел, остальное упорядочено.
5. **Шаблонный код портов.** Модули-структуры собрали порты рядом с контрактом, но
   `declare()` всё ещё повторяет типы дважды (`produces<E>()` и `writer<E>()`).
   Следующий шаг — `ModuleContext`, который выдаёт порты по контракту сам.
6. ~~Ссылки на сущности — голые индексы~~ — решено: `ECS::Entity` с поколением
   передаётся в событиях двумя полями (index, generation).

### RendererSystem

1. ~~Нет текста~~ — решено (конспект 7): `Font` (stb_truetype + stb_rect_pack, кириллица; запасной — stb_easy_font),
   `Renderer2D::draw_text` с переносом, выравниванием и тенью, `App::ui_font()`. Старые игры пока рисуют
   числа полосками — их можно перевести на текст.
2. **Нельзя обновить текстуру через Renderer2D** (`texture()` константный). Поэтому FallingSand
   рисует до ~27 000 квадов, хотя мог бы обновлять одну текстуру размером с сетку.
   Нужен `Renderer2D::update_texture(handle, image / область)`.
3. **Статичная геометрия пересобирается каждый кадр** (тайлы Colony, клетки FallingSand).
   Для воксельного мира нужны кэшированные буферы чанков.
4. ~~`advance_animations` только для плотного массива~~ — обойдено: вспышки FallingSand хранят
   `AnimationState` отдельным компонентом ECS, и его пул — плотный массив. Колонисты Colony

7. **3D есть, но без теней и инстансинга** (конспект 7): Renderer3D рисует каждую сетку отдельным вызовом.

8. **Нет внешних текстур в Renderer2D.** Лицо карты, нарисованное в Framebuffer, нельзя показать спрайтом в 2D —
