# Character — конспект для изучения и переписывания

`src/include/Character/Character.hpp` и `src/code/Character.cpp` (~190 строк). Зависит от `Math` и `ECSSystem` — **не от ландшафта**.

## 1. Зачем и главная идея

Управляемый персонаж: капсула из трёх сфер, которая ходит, прыгает, имеет личную ману и гримуар заклинаний. Данные — **компоненты ECS**, логика — одна функция `step(world, surface)` на весь мир (data-oriented: нет класса `Character`, есть набор компонентов на сущности).

Главное решение: **столкновения идут по интерфейсу `Math::SdfField`**. Персонаж не знает, по чему идёт — ландшафт, плоскость (`PlaneSdf`) или планета (`SphereSdf`). Поэтому тесты движения на плоскости мгновенные, а тот же код работает на настоящем мире.

## 2. Компоненты

| Компонент | Поля | Смысл |
|---|---|---|
| `Position` | `value`, `previous` | низ капсулы (под ногами) и позиция прошлого тика (интерполяция отрисовки) |
| `Velocity` | `value` (FVec3) | скорость, м/с |
| `Collider` | `heights[3]`, `radius`, `count` | центры сфер над ногами: 0,4 / 0,9 / 1,4 м, радиус 0,4 м |
| `ManaPool` | `current`, `max`, `regen` | личная мана (`Math::Mana`), восстанавливается сама (в секунду) |
| `Grimoire` | `slots[3]` (имена), `selected` | три слота со ссылками на программы **по имени** (из `Runes::ProgramLibrary`) — перечитанный файл подхватывается на лету |
| `Motor` | `wish`, `jump`, `grounded` | желаемое направление в XZ (длина ≤ 1), одноразовый запрос прыжка, стоит ли на опоре |

`Config` (общая для всех): ходьба 5 м/с, прыжок 7,5 м/с (≈ 2,9 м — можно выпрыгнуть из ямы-шара r=2 м), `air_control` 1/8, терминальная скорость 40 м/с, тик 1/60, проходимый склон `normal.y ≥ 3/5`, прилипание к земле до 15 см, 2 подшага столкновений.
ZII: `Motor{}` — стоит и не идёт; `Position`/`Velocity` нулевые.

## 3. Как устроено

### 3.1 `spawn` и `eye`
`spawn(world, feet, mana, grimoire)` — создаёт сущность со всеми шестью компонентами. `eye(world, who)` — позиция глаз (+1,6 м над ногами) для луча прицеливания.

### 3.2 `step` — один тик (для каждой сущности по порядку `entities_of<Position>()`)
Обход через `entities_of` — **по возрастанию id**, а не по порядку в пуле: результат не зависит от истории удалений (детерминизм). Для каждой:
1. **Мана:** `current = min(max, current + regen·tick)`.
2. `previous = value` (для интерполяции).
3. **Управление:** целевая скорость `wish·walk_speed` по XZ; на земле скорость приближается полностью (`control = 1`), в воздухе — на долю `air_control`.
4. **Прыжок:** только если `jump && grounded` → `velocity.y = jump_speed`, `grounded = false`; запрос `jump` всегда сбрасывается.
5. **Гравитация:** в воздухе `v += gravity(pos)·tick`; на земле отрицательная вертикальная скорость обнуляется. `clamp(v.y, ±terminal)`.
6. **Подшаги** (`substeps = 2`, против «проскакивания» тонких стен): `pos = advance(pos, v, tick/substeps)` → `resolve`.
7. **Прилипание:** если опоры нет и `v.y ≤ 0`, смотрим землю под нижней сферой; зазор ≤ `snap_distance` и склон проходим → опускаем персонажа на зазор (не «отрывается» на спуске и не зависает над землёй) и ещё раз `resolve`.
8. `grounded = support && v.y ≤ 0`.

### 3.3 `resolve` — выталкивание из породы
До 4 итераций: для каждой сферы `d = sdf.sample(centre) − radius`; `d < 0` — проникновение. Нормаль — `gradient` (запасная — вверх); позиция сдвигается вдоль нормали на глубину `−d`; компонента скорости «в породу» (`dot(v, n) < 0`) гасится (`v −= n·into`); если `n.y ≥ walkable_slope` — есть опора. Возвращает, упёрся ли в ступаемый склон.

### 3.4 `hash_characters`
Вклад в хеш симуляции: для каждой сущности по порядку id — `index`, позиция (3×int64), скорость (3×raw), мана, `grounded`. **Не входят** `previous` (производное), `Grimoire` (строки — это данные библиотеки, а не состояние), `generation`.

## 4. Как использовать

```cpp
ECS::World world;
ECS::Entity hero = Character::spawn(world, feet, {.current = 10_mana, .max = 100_mana, .regen = 5_mana}, {});
world.get<Character::Motor>(hero)->wish = {1_fx, 0_fx, 0_fx};   // команда Move ставит желаемое направление
world.get<Character::Motor>(hero)->jump = true;                 // команда Jump
Character::step(world, surface);                                // каждый тик; surface — любой Math::SdfField
Math::WorldPos eye = Character::eye(world, hero);               // луч для заклинания
```
Где это в проекте: `SpellSim::Simulation::tick` — `Move`/`Jump`-команды заполняют `Motor`, затем `Character::step(world, terrain)`; `Runes::SpellSystem` читает `ManaPool`/`Grimoire`; `Challenge::Referee` читает `Position`; тесты — на `PlaneSdf`/`SphereSdf` без мира.

## 5. Что менять осторожно

- **Любое изменение формул движения меняет хеши** → обновление golden (`tools/update_golden.sh`). Порядок шагов в `step` — часть детерминизма.
- Не обходи сущности через `view().each` — только `entities_of` (см. `ECSSystem`, п. 5).
- `walkable_slope`, `snap_distance` и число подшагов связаны: прилипание без проверки наклона «приклеит» к стенам, без подшагов быстрые падения проходят сквозь тонкие слои.
- Один персонаж ≠ один игрок: сейчас `SpellSim` управляет **одним** персонажем (команда без идентификатора игрока). Мультиплеер потребует `player_id` в команде (см. конспект 15/16).
- `Grimoire` хранит **строки** — компонент не trivially copyable; не клади его в пулы, требующие `ZeroInitializable`, и не хешируй побайтово.
- `resolve` ограничен 4 итерациями: очень глубокое проникновение (телепорт в породу) вытолкнется не полностью.

## 6. Упражнения для переписывания

1. Замени капсулу из трёх сфер одной сферой и сравни, на каких формах ландшафта поведение отличается (ступеньки, узкие щели).
2. Добавь приседание: `Motor::crouch` уменьшает `Collider::count` — как не сломать «опору» и хеш?
3. Реализуй коллизию между персонажами (выталкивание друг из друга) — каким должен быть порядок, чтобы результат не зависел от id?
4. Добавь `player_id` в `Motor` и сделай `step` обрабатывающим несколько персонажей с разными командами.
5. Сделай движение по планете (`SphereSdf`) с гравитацией к центру: какие места `step` предполагали «вниз = −Y»?
