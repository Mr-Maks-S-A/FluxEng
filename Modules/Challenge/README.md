# Challenge — игровой цикл поверх симуляции

Симуляция сама по себе — сцена без цели. `Challenge` добавляет то, что заставляет **рисовать заклинание**: мир, в котором просто
так не пройти, цель, пределы и планки «хорошо». Всё это данные; правил симуляции модуль не меняет и мир только **читает**.

Подключение: `#include <Challenge/Play.hpp>`, цель `engine::Challenge` (входит в `engine::Gameplay`). Зависит от `SpellSim`.

```cpp
const Challenge::Level& level = *Challenge::find_level("fort");
SpellSim::Simulation sim(level.config);             // сид + правки поверх сида + точка появления + слоты гримуара
Challenge::install_library(level, sim);             // стартовые заклинания уровня
Challenge::Referee referee(level);
// каждый тик:
sim.tick(commands);
referee.observe(sim);                               // читает мир; после исхода замирает
hud(referee.status_line());                         // «Крепость · 11.4/60 с · мана 959 · касты 5/8 · рун 4 · ПОБЕДА ***»
if (referee.status() != Challenge::Status::Running) show(referee.stars(), referee.loss());
```

## Уровень

| Поле | Что |
|---|---|
| `config` | `SpellSim::Config`: сид, `setup` (шары породы/пустоты поверх сида: стены, обрывы), сдвиг появления, слоты гримуара |
| `library` | заклинания, доступные с начала (имя, текст `.rune`); пустой слот — заклинание рисует игрок |
| `goal` | `Reach` (дойти), `Carve` (в точке пустота), `Raise` (в точке порода) |
| `limits` | пределы, нарушение — поражение: `max_ticks`, `max_casts`, `max_program_runes`, `max_mana_spent` |
| `par` | планки на звёзды: ★ победа, ★★ трат маны не больше, ★★★ и программа не длиннее |
| `needs_spell` | без заклинаний пройти нельзя (тесты проверяют «стоя на месте» и «просто идти» — должны проигрывать) |

Встроенная кампания (`campaign()`): **Первый шаг** (дойти) → **Шахта** (прицеливание, цена шара r=3 — 810 из 1000) → **Курган**
(платить из окружения: предел трат меньше цены, а поле вокруг конечно) → **Крепость** (прорубиться сквозь кольцевую стену, касты
надо экономить). Рельеф уровней строится по сиду, а не «магическими числами»: стены стоят по земле, цели — там, куда виден луч.

## Эталонные решения и «играть без окна»

`reference_solution(id)` — программы + бот: бот целится лучом и ждёт ману, как игрок; решения не имеют собственного состояния.
`Challenge::play(level, solution, session*)` прогоняет решение тем же путём, что игра: программы уходят блобом и командой `SetProgram`
через `Replay::Driver`, поэтому прогон можно записать (`Session::record`) и воспроизвести тем же вызовом с теми же хешами.
Своё решение — `Solution{ programs, steps, policy }` (тексты `.rune` по слотам, сценарий по тикам, бот).

```cpp
Challenge::Solution s;
s.programs = {{0, "TARGET\nPUSH 1.75\nCARVE\nHALT\n"}};                         // слот 0, уйдёт командой SetProgram
s.steps = {{30, SpellSim::cast_command(0, Runes::ManaSource::Personal, down)}};  // выстрел на тике 30
auto outcome = Challenge::play(level, s);                                       // статус, метрики, звёзды, хеши
```

## Сеть

`level_hash(level)` — хеш настройки уровня: передаётся в `Net::LockstepConfig::config_hash`, чтобы пиры разных версий уровня не играли
вместе. Номер уровня — часть настройки прогона, как гримуар: файл записи + номер уровня однозначно задают повтор.

Примеры: `01_play_campaign` (вся кампания эталоном), `02_custom_level` (свой уровень в коде, две попытки с разными звёздами).
Тесты: `ChallengeTests`; бенчмарки: `ChallengeBenchmarks` (судья ≈ 60 нс на тик против ≈ 1,4 мкс тика симуляции; создание мира и прохождение уровня).
