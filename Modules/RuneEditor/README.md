# RuneEditor — редактор графов рун без GPU

Модель визуального редактора заклинаний: **правки как данные**, undo/redo, живая диагностика, раскладка, управление
мышью и автосохранение в журнал с избыточностью. Всё работает без окна — поэтому всё покрыто тестами; рисование
(цель `RuneEditorView`) — тонкий слой сверху.

Подключение: `#include <RuneEditor/Editor.hpp>` (+ `Analysis`, `Controller`, `Layout`, `Autosave`), цель `engine::RuneEditor`
(зависит от `Math`, `Runes`, `EventLog`).

```
 мышь ──Controller──► Op ──► Editor::execute ──► Graph ──analyze──► байт-код + проблемы по узлам + цена
 тест / повтор / сеть ──────┘        │ observer
                                      └──► Autosave ──► журнал EventLog (снимок + правки)
```

| Часть | Что делает |
|---|---|
| `Op`, `Editor` | единственная точка изменения графа; недопустимые правки (цикл, неверная ширина) отклоняются; история снимками; группы `begin/end`; выбор; `preview_move` не шумит |
| `Analysis` | `compile_mapped` + проблемы по узлам (ошибки и предупреждения: недостижимый, неиспользуемый) + цена прохода; `source[pc]` → узел для подсветки трассы |
| `Geometry` | круглые глифы: входы слева дугой, значение/следующий — справа, ветка — снизу; рёбра Безье; `pick` (порт → узел → ребро) |
| `Layout` | `auto_layout`: колонки по ходу управления, значения левее потребителей |
| `Controller` | жесты: перетащить узел, потянуть ребро, поднять конец ребра, рамка, сдвиг холста, масштаб |
| `Autosave` | снимок + правки в журнал; `recover` чинит по чётности и собирает последний граф |

Примеры: `examples/01_edit_and_recover.cpp` (весь цикл от жестов до восстановления после порчи носителя).

## Принципы

- **Правка — это данные.** `Op` — простая структура; то, что делает мышь, можно записать, воспроизвести и отправить по сети.
- **Редактор не доверяет себе.** `Editor::execute` проверяет каждую правку, а не только интерфейс.
- **Нумерация узлов зависит только от содержимого графа** (`Graph::remove` освобождает старший номер) — повтор правок по снимку даёт тот же граф.
