# EventLog — конспект для изучения и переписывания

`src/include/EventLog/{Journal,Storage,ErasureCode,BusAdapter}.hpp`, `src/code/{Journal,Storage,ErasureCode}.cpp` (~910 строк). Основной модуль зависит от `Math` (CRC-32C); связка с шиной — отдельная цель `EventLogBus` (добавляет `EventSystem`).

## 1. Зачем и главная идея

Дописываемый в конец **журнал событий, который переживает повреждение носителя и обрыв записи**. Возвращённая запись всегда достоверна (прошла CRC); то, что восстановить нельзя, названо в отчёте по номерам.
Три уровня защиты:
1. **Запись проверяет сама себя** (маркер + CRC-32C).
2. **Блок проверяет сам себя** (CRC + номер полосы + номер блока).
3. **Полоса из `k` блоков данных + `m` блоков чётности (Рид—Соломон):** любые `m` блоков полосы можно потерять и восстановить.

Это основа файлов записи повторов (`Replay`) и автосохранения (`RuneEditor`).

## 3. Как устроено

### 3.1 Раскладка файла
```
[заголовок A 32 Б][заголовок B 32 Б] полоса 0 | полоса 1 | …
заголовок: magic «FXLJ», версия, k, m, block_size, CRC-32C
полоса: [блок 0 … k−1 данных][блок k … k+m−1 чётности]
блок на проводе: [crc 4][номер полосы 4][номер блока 2][резерв 2][данные block_size]
```
`block_offset(config, stripe, block)` = `64 + stripe·(k+m)·(12+bs) + block·(12+bs)` — для инструментов и **тестов, имитирующих повреждения**. Две копии заголовка: достаточно любой одной.

### 3.2 Записи
Логический поток: подряд идущие **записи** `[sync 5A A5][длина u32][номер u64][тик u32][тип u32][данные][CRC-32C]`; запись может пересекать границы блоков. `type` = FNV-1a (32 бита) от `E::event_name` — одинаков на любой машине. Номера сквозные.
`Writer::append` дописывает запись в буфер `m_pending`; когда накопилось `k·block_size` — `emit_stripe`: режет на `k` блоков, считает `m` блоков чётности, пишет полосу. `flush()` **добивает полосу нулями** (поэтому частый flush расходует место) и вызывает `storage.flush()` (fsync). Деструктор делает flush недописанной полосы.

### 3.3 Код Рида—Соломона (`ErasureCode`)
- Поле GF(2⁸) с примитивным полиномом `0x11D`; таблицы `exp`/`log` и **полная таблица произведений 256×256** (умножение одним обращением); `exp` удвоена, чтобы не брать `% 255`.
- Матрица чётности — **матрица Коши** `C[j][i] = 1/(x_j + y_i)`, `x_j = j`, `y_i = m + i` (все различны) → любая квадратная подматрица `[единичная; C]` обратима → восстановление **любых `m` стираний**.
- `encode`: `parity_j = Σ_i C[j][i]·data_i` (`mul_add` над байтами).
- `reconstruct`: если стёрто больше `m` — `false`. Иначе выбираются `k` уцелевших блоков (сначала данные, потом чётность), строится матрица `k×k` (единичная для данных, Коши для чётности), **Гаусс—Жордан над GF(2⁸)** даёт обратную; потерянные блоки данных = `Σ inverse·уцелевшие`; потерянная чётность пересчитывается из полных данных.

### 3.4 Чтение с восстановлением (`read_all`)
1. Заголовок: читается любая валидная копия; если одна испорчена — `header_repaired`, при `repair` обе переписываются. Обе испорчены → ошибка.
2. Для каждой полосы: проверка каждого блока (`CRC`, номер полосы, номер блока; недописанный в конце — как стёртый); `reconstruct`; в отчёте `blocks_corrupt/repaired/lost`, `stripes_damaged/lost`; при `repair` плохие блоки переписываются заново.
3. Блоки данных идут в **логический поток**; блок потерянной полосы помечается «дырой».
4. Поиск записей: на дыре — к началу следующего блока; на маркере `sync` проверяются длина, границы, отсутствие дыры внутри и CRC; нашли — запись принята; нет — `bytes_skipped++` (нули — добивка, не мусор). **Дубли номеров игнорируются** (ложный маркер внутри данных не создаст запись). Пропуск номеров → `Gap{first, last}` и `records_lost`.
5. `Writer::resume`: чинит журнал, берёт `последний номер + 1` и дописывает с **новой** полосы.

### 3.5 Накладные расходы и выбор `k`, `m`
≈ `m/k` (+ 12 байт на блок): 8+2 по 4 КиБ — четверть объёма. `m = 1` — как RAID-5, `m = 2` — RAID-6. `k + m ≤ 255`. Номер полосы на проводе — `u32` (предел ≈ 4·10⁹ полос).

### 3.6 Адаптер шины
`record(writer, tick, reader)` пишет все события канала, видимые читателю в этом тике. `Replayer` выбирает записи одного тика (бинарный поиск по неубывающим тикам) и `emit<E>(writer)` отправляет события нужного типа в шину.

## 4. Как использовать

```cpp
struct Hit { std::int32_t target, damage; static constexpr std::string_view event_name = "game.hit"; };

EventLog::MemoryStorage storage;                  // или EventLog::FileStorage::open(path, Mode::Create)
auto writer = EventLog::Writer::create(storage, {.data_blocks = 8, .parity_blocks = 2}).value();
writer.append(tick, Hit{3, 25});
writer.flush();                                   // устойчивая точка

auto read = EventLog::read_all(storage).value();  // записи + RecoveryReport
for (const auto& r : read.records) if (auto hit = EventLog::decode<Hit>(r)) apply(*hit);
if (!read.report.clean()) log(read.report);

EventLog::repair(storage);                        // переписать исправленные блоки
auto again = EventLog::Writer::resume(storage).value();   // продолжить после перезапуска
```
Где это в проекте: `Replay::Session` пишет **файл записи повтора как журнал** (потоково, оборванные и повреждённые читаются; `ReplayTool repair`); `RuneEditor::Autosave`; `Sandbox/world_journal` («мир = сид + журнал правок»); `ModuleProof`.

## 5. Что менять осторожно

- **Формат файла и версия** (`file_version = 1`) — часть файлов записей и golden-эталонов; любое изменение раскладки блока/записи = новая версия и чтение старой.
- `emit_stripe` и `read_all` обязаны совпадать по раскладке и порядку полей (`block_offset` публичный и используется тестами повреждений).
- Блоки чётности считаются по **всему** `block_size`, а не по заполненной части — поэтому добивка нулями при `flush` корректна и восстанавливаемость сохраняется.
- Хвост журнала при обрыве: потеря «хвоста» **не видна** в `gaps` (нет следующей записи, по номеру которой её увидеть) — это сказано в документации; учитывай при проверках целостности.
- Маркер `5A A5` может случайно встретиться внутри данных — защита: CRC записи + границы + проверка возрастания номера; не ослабляй.
- `read_all(storage, true)` пишет в хранилище — не вызывай на чужом файле без нужды; `verify` ничего не меняет.
- `max_payload = 1 МиБ` и `block_size ∈ [64, 1 МиБ]` проверяются в `validate`.

## 6. Упражнения для переписывания

1. Замени Коши-матрицу на Вандермонда — покажи на тесте, при каких стираниях она перестаёт быть обратимой (подсказка: нужна «систематическая» форма).
2. Добавь ротацию сегментов (`journal.000`, `journal.001`) и индекс тик → полоса для быстрого поиска (идея из README).
3. Реализуй сжатие записей (например, дельта по тику) без потери восстановимости: что должно остаться вне сжатого потока?
4. Напиши инструмент `journal_corrupt` (портит случайные блоки) и свойство «любое число порч ≤ m на полосу не теряет ни одной записи» на случайных данных.
5. Добавь третий вид `Storage` (сетевой/сегментный) и проверь, что `Writer`/`read_all` не меняются.
