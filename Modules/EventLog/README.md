# EventLog — журнал событий с избыточностью

Дописываемый в конец журнал событий, который **переживает повреждение носителя и обрыв записи**: испорченные блоки
восстанавливаются по чётности (код Рида—Соломона), а то, что восстановить нельзя, названо в отчёте по номерам записей.
Возвращённая запись всегда достоверна — она прошла CRC.

Подключение: `#include <EventLog/Journal.hpp>`, цель `engine::EventLog` (зависит от `Math`).
Связка с шиной — `#include <EventLog/BusAdapter.hpp>`, цель `engine::EventLogBus` (добавляет EventSystem).

## Как устроена защита

```
 события ──► записи  [sync | длина | номер | тик | тип | данные | CRC-32C]       логический поток
                │            └─ каждая запись проверяема сама
                ▼  режем на блоки и группируем по k штук
 полоса:  [данные 0] … [данные k−1] [чётность 0] … [чётность m−1]              физический слой
          у каждого блока: CRC-32C, номер полосы, номер блока                   любые m блоков полосы можно потерять
```

| Что случилось | Что делает читатель |
|---|---|
| испорчено ≤ m блоков полосы (в т. ч. чётности) | восстанавливает **полностью**, отчёт: `blocks_repaired` |
| испорчено > m блоков (полоса потеряна) | читает уцелевшие записи, «перепрыгивает» дыру по маркеру и CRC; потерянные номера — в `gaps` |
| разрушена одна из двух копий заголовка | читает по второй; `repair` восстанавливает копию |
| обрыв записи (питание, сбой) | недописанные блоки — стёртые: чётность восстанавливается, потеря данных видна в отчёте |
| разрушены обе копии заголовка | ошибка: форма журнала неизвестна |

Накладные расходы ≈ m/k (+ 12 байт на блок): при 8 + 2 по 4 КиБ — четверть объёма. Выбирайте k и m под носитель:
m = 1 — как RAID-5 (одна потеря на полосу), m = 2 — как RAID-6; чем больше m, тем больше «битых секций подряд» выдерживает полоса.

## Быстрый старт

```cpp
struct Hit { std::int32_t target, damage;  static constexpr std::string_view event_name = "game.hit"; };

EventLog::MemoryStorage storage;                           // или EventLog::FileStorage::open(path, Mode::Create)
auto writer = EventLog::Writer::create(storage, {.data_blocks = 8, .parity_blocks = 2}).value();
writer.append(tick, Hit{3, 25});                           // типизированно (тип — FNV-1a от имени); или append(tick, type, bytes)
writer.flush();                                            // устойчивая точка; частый flush расходует место (добивка полосы)

auto read = EventLog::read_all(storage).value();           // записи + RecoveryReport
for (const EventLog::Record& r : read.records)
    if (auto hit = EventLog::decode<Hit>(r)) apply(*hit);
if (!read.report.clean()) log(read.report);                // blocks_repaired, gaps, records_lost …

EventLog::repair(storage);                                 // переписать исправленные блоки: журнал снова целый
auto again = EventLog::Writer::resume(storage).value();    // после перезапуска: починить и продолжить нумерацию
```

## Состав

| Часть | Что |
|---|---|
| `Writer`, `read_all`, `verify`, `repair` | журнал: запись, чтение с восстановлением, проверка, исправление на месте |
| `Record`, `Gap`, `RecoveryReport` | запись; пропуск номеров; что нашли и что исправили |
| `ErasureCode` | Рид—Соломон над GF(2⁸), матрица Коши: любые `m` известных потерь из `k + m` блоков. Используется отдельно для любых данных |
| `Storage`, `MemoryStorage`, `FileStorage` | куда пишем; память — для тестов (можно портить байты), файл — с `fsync` |
| `block_offset`, `block_wire_size` | раскладка файла: где лежит блок (для инструментов и имитации повреждений) |
| `type_id`, `LoggableEvent`, `decode<E>` | типизированные события (имя → идентификатор, проверка типа и размера при чтении) |
| `record`, `Replayer` (BusAdapter) | события шины → журнал и журнал → шина |
| `Math::crc32c` | контрольная сумма (в модуле Math) |
