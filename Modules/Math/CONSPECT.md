# Math — конспект для изучения и переписывания

Читается вместе с кодом: `src/include/Math/*.hpp` (595 строк на весь модуль, только `Math.cpp` — реализация). Зависимостей нет — с него удобно начинать.

## 1. Зачем модуль и главная идея

Симуляция должна давать **побитово одинаковый результат на любой машине и в любом порядке потоков**: на этом стоят запись/повтор (`Replay`), сеть lockstep (`Net`) и golden-эталоны.
Поэтому внутри симуляции нет `float`/`double`, `std::rand` и системного времени. Всё, что считает мир, — целые числа:

- `Fixed` — Q16.16 на `int32` (1.0 = 65536);
- `WorldPos` — позиция на `int64` (тот же масштаб 1/65536 м, но диапазон огромный);
- `Rng` — генератор с сидом; `Hasher` / `crc32c` — хеши состояния и целостность.

`float` допустим только на **границе**: превращение мыши/камеры в команды (`from_double`, `quantize_direction`) и отображение (`to_double`).
Эти функции помечены в комментариях «симуляция не вызывает» — это правило, а не техническое ограничение; нарушить его компилятор не помешает.

## 3. Как устроено

### 3.1 `Fixed`
- Хранится `raw` (int32). `from_raw` — «как есть», `from_int(5)` = `5 << 16` с насыщением, `from_ratio(num, den)` = `num·65536/den` (**усечение к нулю**).
- Сложение/вычитание считаются в int64 и **насыщаются** (`saturate`): переполнение не оборачивается, а упирается в `min()/max()`. Значит `Fixed::max() + 1` остаётся `max()`.
- Умножение: `(int64)a.raw * b.raw / 65536` — деление в C++ усекает к нулю, поэтому `a*b == -((-a)*b)`: симметрично. Это важно для маны: потоки в разные стороны не оставляют «хвостов».
- Деление: `a.raw * 65536 / b.raw`; на ноль возвращает `max()`/`min()` по знаку делимого (симуляция не падает).
- `floor()` — арифметический сдвиг, то есть к минус бесконечности (`-0.5` → `-1`); в отличие от `*`, которое усекает к нулю. Две разные функции округления в одном типе — частый источник ошибок.
- `_fx`: `1.5_fx` **округляет к ближайшему**, а `from_ratio(3, 2)` усекает. Для «красивых» констант они совпадают, для `1/3` — нет.
- `sqrt(Fixed)` = `isqrt(raw << 16)`: корень от `raw·65536` даёт raw результата. `isqrt` — побитовый алгоритм без float (цикл по степеням четвёрки).

### 3.2 `Mana`
Обёртка над `Fixed` с намеренно урезанным набором операций: `Mana ± Mana`, `Mana * Fixed`, `Mana / Fixed`, `Mana / Mana → Fixed`, сравнения. `Mana + Fixed` и `Mana * Mana` не компилируются — это защита от путаницы «мана ↔ метры ↔ радиус».
Конструктор из `Fixed` — `explicit`; обратно — `.value` или `.raw()`.

### 3.3 Векторы и позиция
- `FVec3` — три `Fixed`; `dot` считает в Fixed (с насыщением на каждом шаге), `length` — в int64 через `isqrt` (точнее).
- `WorldPos` — три `int64` (единицы 1/65536 м). `to_fvec` насыщается за ±32 км, поэтому вектор **от** позиции годится только «рядом».
- `advance(p, v, scale)` = `p + v·scale` в int64 без потери точности — так шагает движение.
- `distance_sq_raw` складывает квадраты в int64 без насыщения. **Ловушка:** при разности порядка десятков километров по осям сумма квадратов уже может не влезть в int64 — для дальних расстояний нужен другой путь (сейчас мир меньше).
- `gravity` — константа `(0, −9.81, 0)` в виде `raw = −642908`; написана как функция позиции, чтобы потом подставить планеты.
- `normalize` делит каждую компоненту на длину в int64; нулевой вектор остаётся нулевым.

### 3.4 `Rng` и шум
- `Rng` — SplitMix64: `state += 0x9E37…; return mix64(state)`. `below(n)` берёт старшие 32 бита и масштабирует умножением (почти без смещения, без `%`). `unit()` = старшие 16 бит как raw → `[0, 1)`.
- `mix64` — отдельная функция: на ней же стоят `lattice_value` и хеширование координат.
- `value_noise`: значения решётки из `mix64(seed ^ mix64(x | z<<32))`, интерполяция сглаженной кубической (`3t²−2t³`) по двум осям. Дробная часть берётся как `raw & 0xFFFF` — корректно и для отрицательных координат (двоичное дополнение).
- `fbm`: октавы с амплитудой ×½ и частотой ×2, нормировка на сумму амплитуд, результат ≤ `0xFFFF` (чуть меньше 1.0). Сид каждой октавы смещается на `i·0x9E37`.

### 3.5 Хеши
- `Hasher` — FNV-1a по байтам, целые добавляются **little-endian** (хеш не зависит от платформы). `add_span` хеширует блок как байты — именно так считаются хеши ландшафта и поля маны. Если у типа в блоке есть **padding**, он попадёт в хеш: хешируемые структуры должны быть плотными.
- `content_hash(bytes)` = FNV от длины + байтов: «адрес по содержимому» для блобов (программы заклинаний в записи и сети).
- `crc32c` — таблица считается при компиляции (`constexpr`); `seed` позволяет считать по частям. FNV быстрее, CRC надёжнее ловит порчу — поэтому FNV для сравнения состояний, CRC — для файлов/пакетов.

### 3.6 `SdfField` и луч
`sample(pos) < 0` — внутри, `> 0` — снаружи. `gradient` по умолчанию — центральные разности с шагом 25 см (6 вызовов `sample`). `raycast` — sphere tracing: шаг = `0.8·d`, но не меньше 5 см; попадание при `d ≤ 2 см`; не больше 256 итераций (то есть может вернуть «ничего» раньше `max`, если луч скользит вдоль поверхности).

## 4. Как использовать

```cpp
using namespace Math::literals;
Math::Fixed g = Math::Fixed::from_ratio(981, 100);       // 9.81
Math::Mana cost = 240_mana;
Math::WorldPos p = Math::WorldPos::from_meters(10, 0, -4);
p = Math::advance(p, {1_fx, 0_fx, 0_fx}, Math::Fixed::from_ratio(1, 60));   // шаг одного тика

Math::Rng rng(seed);                  // один Rng на подсистему, сид из конфигурации
Math::Hasher h; h.add(tick); h.add_signed(p.x);   // хеш состояния
std::uint64_t hash = h.value();

auto hit = Math::raycast(world_sdf, origin, Math::quantize_direction(dx, dy, dz), 50_fx);
```

Где это стоит в проекте: `Terrain` (SdfWorld реализует `SdfField`), `Character` (движение по SDF), `Runes` (стоимость, радиусы), `ManaField` (Mana), `Replay`/`EventLog`/`Net` (CRC и content_hash), `SpellSim` (Rng, Hasher).

## 5. Что менять осторожно

- **Любое изменение округления/насыщения/шума меняет хеши симуляции** → падают golden-эталоны (`SpellSim/tests/golden`) и записи. Это ожидаемо; пересоздаются `tools/update_golden.sh`. Меняй осознанно и одним коммитом с эталонами.
- Менять `frac_bits` нельзя «просто так»: `WorldPos` и `Fixed` связаны одной шкалой, константы вроде `-642908` и `0xFFFF` завязаны на 16 бит.
- Добавляя функцию в Math, проверь: нет ли в ней `float`, нет ли UB при переполнении int64 (знаковое переполнение — UB, насыщение — нет).
- Новые типы-«единицы» (как `Mana`) делай по тому же шаблону: `Fixed` внутри, `explicit` конструктор, только осмысленные операции.

## 6. Упражнения для переписывания

1. Перепиши `isqrt` через float и сравни результаты на всех `uint64` из набора краевых случаев — увидишь, где float ошибается на больших числах.
2. Добавь `Fixed::round()` (к ближайшему) и тест симметрии для отрицательных; реши, нужен ли он вообще в симуляции.
3. Напиши `Meters`/`Seconds` как отдельные типы по образцу `Mana` и найди в проекте места, где их не хватает.
4. Реализуй `distance` без переполнения для больших разностей (масштабируй вниз перед квадратом) и проверь границу.
5. Замени шум на gradient noise (Перлин) на Fixed; сравни скорость `MathBenchmarks`.
