# Challenge — конспект для изучения и переписывания

`src/include/Challenge/{Level,Referee,Play}.hpp`, `src/code/{Campaign,Referee,Solutions,Play}.cpp` (~670 строк). Зависит от `SpellSim` (и через него от всего геймплея), `Math`, `Replay`, `Runes`, `Terrain`, `Character`. **Мир только читает**, правил симуляции не меняет.

## 1. Зачем и главная идея

Симуляция сама по себе — сцена без цели. `Challenge` добавляет то, что заставляет **рисовать заклинание**: мир, в котором просто так не пройти, цель, пределы и планки «хорошо». Всё это **данные**:

```
Level = мир (SpellSim::Config) + библиотека стартовых заклинаний + Goal + Limits + Par
Referee  читает const Simulation после каждого тика и решает исход
Solution = программы + сценарий по тикам + бот   →   play(level, solution) прогоняет «как игрок», без окна
```
Эталонные решения (`reference_solution`) **доказывают, что каждый уровень проходим**; тесты требуют, чтобы «стоять на месте» и «просто идти» проигрывали везде, где нужна магия.

## 3. Как устроено

### 3.1 Уровень
- `config` — `SpellSim::Config`: сид, `setup` (шары породы/пустоты поверх сида: стены, обрывы), сдвиг появления, слоты гримуара.
- `library` — заклинания, доступные с начала (имя, текст); пустой слот — рисует игрок.
- `goal`: `Reach` (дойти в пределах `radius` от точки), `Carve` (в точке пустота), `Raise` (в точке порода).
- `limits` (ноль = без предела): `max_ticks`, `max_casts`, `max_program_runes`, `max_mana_spent`; нарушение — поражение.
- `par`: ★ победа; ★★ ещё и трат маны ≤ `par.mana_spent`; ★★★ ещё и программа ≤ `par.program_runes` (ноль в планке = «условие выполнено»).
- `needs_spell` — без заклинаний пройти нельзя (проверяют тесты).

### 3.2 Встроенная кампания (`campaign()`)
**Первый шаг** (дойти) → **Шахта** (прицеливание; шар r=3 стоит 810 из 1000 маны) → **Курган** (предел трат меньше цены шара: платить надо из окружающего поля, а оно вокруг конечно ≈ 320) → **Крепость** (кольцевая стена ≈ 5 м, прорубаться по шагам, ≤ 8 кастов).
Рельеф строится `Builder` **по сиду**, а не магическими числами: стены стоят по земле (`ground`), цели — там, куда виден луч (`visible_point`: проверяет, что рельеф не заслоняет прицельный луч), `ring` ставит кольцо шаров в четыре слоя по высоте (не перелезть и не подкопаться).
**Осторожно:** `Builder` считает в `double` с `std::cos/sin` и один раз превращает в Fixed через `from_double` — это **построение настройки**, не симуляция; но результат (позиции шаров) может отличаться между платформами/libm. Защита: `level_hash(level)` входит в `Net::LockstepConfig::config_hash`, и пиры с разным построением уровня не сыграют вместе.

### 3.3 `Referee::observe(sim)` — исход после каждого тика
Порядок (важен):
1. Обновить метрики: тики, касты, неудачные касты, принятые правки (`programs_set`), **траты маны** — сумма падений личной маны между тиками (`m_spent_raw` в сырых единицах, чтобы дробные доли не терялись; восстановление не вычитается), самая длинная программа среди слотов гримуара.
2. Посчитать достижение цели: `Reach` — расстояние от ног до точки (`isqrt` в int64); `Carve/Raise` — знак `terrain.sample(point)` (>0 пустота / <0 порода); `distance()` — подсказка «до цели».
3. **Пределы проверяются раньше победы**: выиграл, нарушив предел на том же тике, — не выиграл (`TooManyCasts`, `TooMuchMana`, `ProgramTooLong`).
4. Победа (`Won`), иначе `max_ticks` → `OutOfTime`.
После исхода судья **замирает** (`observe` ничего не делает). `stars()` — по `Par`; `status_line()` — строка HUD («Крепость · 11.4/60 с · мана 959 · касты 5/8 · рун 4 · ПОБЕДА ***»).

### 3.4 `play(level, solution, session*)`
Собирает `Simulation(level.config)`, `install_library`, `Replay::Driver` (с внешней `Session` или `off`) и `Referee`. На тике 0 уходят `SetProgram`-команды (программы решения как блобы через `driver.submit_blob` — **тем же путём, что в игре**); сценарные шаги `Solution::steps` подаются на своих тиках; `policy` (бот) — каждый тик, кроме повтора. Цикл идёт, пока `Running` и `tick < limit + 1`. Результат `Outcome{status, loss, metrics, stars, distance, ticks_run, hashes, status_line}`. Благодаря этому прогон можно **записать и воспроизвести** (те же хеши). `play_idle` — «ничего не делать» (контрольный проигрыш).

### 3.5 `Solution`
`{programs: [(слот, текст .rune)], steps: [(тик, Replay::Command)], policy: функция(const Simulation&, команды)}`. Бот не хранит собственного состояния — только смотрит на `const Simulation` (целится лучом, ждёт ману как игрок).

### 3.6 Сеть
`level_hash` — хеш мира + цели + пределов; номер уровня — часть настройки прогона, как гримуар: файл записи + номер уровня однозначно задают повтор.

## 4. Как использовать

```cpp
const Challenge::Level& level = *Challenge::find_level("fort");
SpellSim::Simulation sim(level.config);
Challenge::install_library(level, sim);
Challenge::Referee referee(level);
// каждый тик:
sim.tick(commands);
referee.observe(sim);
hud(referee.status_line());
if (referee.status() != Challenge::Status::Running) show(referee.stars(), referee.loss());

// без окна:
Challenge::Solution s;
s.programs = {{0, "TARGET\nPUSH 1.75\nCARVE\nHALT\n"}};
s.steps = {{30, SpellSim::cast_command(0, Runes::ManaSource::Personal, down)}};
auto outcome = Challenge::play(level, s);          // с Replay::Session* — запись/повтор
```
Где это в проекте: `RuneCell2 --level id [--bot]`, `CoopScribe` (`level_hash` в `Net`), `ModuleProof`, тесты кампании.

## 5. Что менять осторожно

- **Порядок проверки «пределы раньше победы»** — часть правил; изменение меняет звёзды и исходы тестов.
- Траты маны считаются как **падения** личной маны: восстановление не вычитается, а случайная утечка маны в `Runes` (провал каста из окружения, см. `Runes`, п. 5) **попадает в траты** и портит звёзды — исправление утечки изменит результаты уровней.
- `Builder` использует `double`/`std::cos`: не переноси его в симуляцию; при изменении уровня пересчитай `level_hash`-зависимые сценарии.
- Все `Level` — статические данные; `campaign()` возвращает `span` на статический массив — не меняй их после старта.
- Один персонаж: `Referee` читает `sim.player()`. Несколько игроков потребуют метрики по игроку.
- `play` ограничивает цикл `limit + 1` тиками, чтобы не зависнуть, даже если `Limits::max_ticks == 0` (тогда 3600).

## 6. Упражнения для переписывания

1. Добавь уровень «Ров» (насыпать мост: `Raise`) — подбери `par` и напиши эталонное решение; тесты «стоять» и «идти» должны проигрывать.
2. Реализуй `Goal::Survive` (дожить N тиков под обстрелом) — какие метрики и какой новый вид сценария нужны?
3. Используй `max_program_runes` в уровне (ограничение длины программы) и покажи, как это меняет эталонное решение.
4. Сделай загрузку уровней из файла (JSON/текст) вместо кода: что должно попасть в `level_hash`?
5. Исправь расхождение `double`/libm: строй стены целочисленно (`Math::isqrt`, таблица синусов в Fixed) и убедись, что хеш уровня одинаков на двух компиляторах.
