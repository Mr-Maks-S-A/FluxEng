## 2. RendererSystem: что добавлено

### 2.1. Слои остались те же

CPU-ядро (без OpenGL, тестируется везде) и GL-бэкенд. Новое легло так:

| CPU-ядро | GL-бэкенд |
|---|---|
| `Core/Geometry3D.hpp` — луч, AABB, плоскость, пирамида видимости | `GL/Mesh` — VAO+VBO+EBO, `VertexLayout`, `BufferUsage` |
| `Scene/Camera3D` — матрицы, `screen_to_ray`, `world_to_screen`, `orbit` | `Renderer3D` — материалы, свет, туман, сортировка, отсечение |
| `Mesh/MeshData` — `Vertex3D` (36 байт) и генераторы | `GL/Framebuffer` — `FramebufferDesc{.depth}`, `uv()`, `read_default()` |
| `Text/Font` — атлас глифов и раскладка | `Renderer2D::add_font / draw_text / measure_text` |
| `Core/Procedural` — шум и картинки из него | `Texture::generate_mipmaps` (после рисования в текстуру) |

### 2.2. Решения, которые стоит сохранить

- **Соглашения 3D**: Y вверх, правая система, камера смотрит вдоль −Z (как `glm::lookAt`). UV — как во всём
  модуле: (0, 0) — левый верх картинки. Поэтому одна и та же картинка одинаково ложится на 2D-спрайт и 3D-сетку.
- **Framebuffer::uv()** — `{(0,1), (1,0)}`. В OpenGL строка 0 текстуры — низ кадра; кадр, нарисованный
  Renderer2D (Y вниз), без этого был бы перевёрнут на 3D-карте. Есть GPU-тест «текст сверху остаётся сверху».
- **Material не владеет текстурой** (`const GL::Texture*`): текстура может быть из Renderer2D, из Framebuffer,
  из чего угодно. Renderer3D хранит только белую 1×1 по умолчанию.
- **Порядок кадра в Renderer3D**: непрозрачные — группами по текстуре (`stable_sort` по указателю),
  прозрачные — от дальних к ближним без записи глубины. После `end()` глубина и culling выключены —
  2D-оверлей рисуется сразу (раньше Voxel полагался на то, что это сделает `Renderer2D::end()`).
- **Font без GPU**: раскладка (UTF-8, перенос по словам, выравнивание, кернинг) возвращает четырёхугольники —
  её проверяют CPU-тесты; Renderer2D только отправляет их в батч. Атлас — белые пиксели, покрытие в альфе,
  поэтому цвет текста — обычное тонирование спрайта, а тень — тот же текст со сдвигом (сортировка устойчива).
- **Font::builtin()** (stb_easy_font) — шрифт без файлов: тесты рендера текста детерминированы на любой машине,
  а игра не падает без системных шрифтов. `Font::find_system_font()` ищет DejaVu/Noto/Liberation/Arial/Segoe;
  `FLUX_FONT` задаёт путь явно.
- **Procedural** — детерминированный шум (stb_perlin), можно звать из задач JobSystem. Это и есть «шум
  в общую математику» из конспекта 6 (4.4): Voxel может перейти на него.

### 2.3. Что ещё узнали

- `GL::Mesh::upload()` для `Static` переиспользует буфер, если размер не вырос (`glBufferSubData`); для
  `Dynamic/Stream` — orphaning, как в Renderer2D.
- Отсечение в Renderer3D работает, только если у сетки есть границы (`upload(MeshData)` их считает; для сырых
  байтов — `set_bounds`).
- Цилиндр, сфера и пластина проверены тестом «все треугольники смотрят наружу» — ошибку обхода
  с включённым culling иначе видно только глазами.

## 3. Core: 3D-игре больше не нужны костыли

| Было (конспект 6, 4.3) | Стало |
|---|---|
| 2D-камера и WASD/колесо работают всегда | `AppConfig::camera_controls = false` |
| `world_size()` обязателен | по умолчанию 1280×720 |
| ввод и загрузка на GPU — внутри `render()` | `Game::frame(app, seconds)` — до тиков, в домене кадра |
| игра сама включает глубину и чистит буфер | App чистит цвет+глубину (`clear_rgba`), затем `Game::render_3d(app, renderer3d)` |
| шрифта нет | `App::ui_font()` / `ui_font_bold()` — системный TTF или встроенный |
| скриншот — `glReadPixels` в App | `Framebuffer::read_default()` + `Image::save_png()` |
| — | `AppConfig::visible = false` — скрытое окно (тесты), без vsync |

Кадр App теперь:

```
poll_events → Game::frame → тики (Game::tick, advance_tick, swap памяти тика)
  → clear (цвет+глубина) → Game::render_3d → Game::render (2D, камера мира) → Game::render_overlay
```

**Исправленная ошибка.** Кнопки мыши App отправлял в шину, читая флаги кадра `InputState::mouse_pressed()`.
Клик, который пришёл между кадрами (например, `Window::inject_mouse_button` — запись/воспроизведение ввода, боты,
тесты), стирался `begin_frame()` до того, как App успевал его прочитать. Теперь кнопки идут подпиской на
`events().mouse_button` — как клавиши: каждое нажатие и отпускание попадает в шину по порядку. Это проверяет
интеграционный тест Core и бот ввода CardDuel.

## 4. CardDuel

### 4.1. Правила — отдельно от графики

`Sandbox/card_duel/Rules.*` → библиотека `CardDuelRules` (EventSystem + JobSystem + MemorySystem, без рендера):

- **`Match` — плоская структура фиксированного размера** (`FixedList<T, N>` вместо `vector`): тривиально
  копируется, удовлетворяет `MemorySystem::ZeroInitializable`. Нулевая партия — «не начата» (ZII).
- 22 карты + жетон: существа (провокация, рывок, божественный щит, боевые кличи) и заклинания
  (урон, лечение, массовый урон, взятие карт, усиление, призыв). Две колоды по 20 карт — разные архетипы.
- `legal_actions / is_legal / apply` — всё, что меняет партию, пишет журнал `Outcome` (урон, смерть, ход…).
  `Action` и `Outcome` — это и есть события шины (`duel.command`, `duel.outcome`).
- `hash(Match)` — по полям, без байтов выравнивания: контрольная сумма прогона.

### 4.2. ИИ на JobSystem и MemorySystem

Каждое допустимое действие проверяется `rollouts` случайными продолжениями хода; оценка = лучшее продолжение
(«план хода») + 0.1 × среднее. Все симуляции — один `parallel_for`: копия партии и список действий живут
в арене потока (`ArenaScope(jobs.scratch())`), результат симуляции `i` пишется в `scores[i]`, свёртка —
в фиксированном порядке. Решение одинаково при любом числе потоков (тест + контрольная сумма игры).
Стоимость: ~0.05–0.15 мс на решение (до ~300 симуляций), 48 продолжений на действие по умолчанию.

### 4.3. Сцена: правила впереди, показ — следом

```
PlayerInput ─┐                                   ┌─▶ Chronicle (spdlog + строки на экране)
AI ──────────┴─ duel.command ─▶ Rules ─ duel.outcome ─┤
                                                 └─▶ Director ── duel.fx ─▶ Effects
```

- **Rules** применяет команды мгновенно. **Director** проигрывает журнал по одной записи с паузами
  (выпад атаки, урон, смерть…) и меняет **сцену ECS**: карты и герои — сущности (`CardView`, `Transform`,
  `Shown`, `Lunge`, `Shake`, `Fade`). Director — единственный, кто создаёт и уничтожает сущности.
- `Shown` — что *показано* на карте; оно отстаёт от `Match` на время показа. Поэтому анимации идут по очереди,
  а ввод и ИИ ждут, пока Director закончит (`busy()`), и ещё два тика, пока команда дойдёт до правил
  (`CommandGate`).
- **Лица карт** рисует Renderer2D (рамка, рисунок из шума, название, текст, кристалл маны, атака/здоровье)
  в Framebuffer с mip-уровнями; кэш по «что написано на карте» (карта + атака + здоровье + щит).
  Раненое существо — новое лицо с красным числом.
- **Effects** — частицы, всплывающие числа и снаряды в `MemorySystem::Pool` (ZII, стабильные адреса);
  каждый снаряд — точечный свет Renderer3D.
- **Выбор мышью**: луч `Camera3D::screen_to_ray` переводится в локальные координаты каждой карты
  (`inverse(model)`) и пересекается с её коробкой. Карта в руке выбирается по своему *месту*, а не по
  поднятой позе — иначе поднятая под курсором карта «убегает» и мигает.
- **Бот ввода** (`--input-bot`) играет за вас настоящими кликами `Window::inject_*`: курсор → луч → выбор →
  `platform.mouse_button` → PlayerInput → команда. Это сквозная проверка всего пути ввода.

## 5. Общие тесты (Tests/integration)

Юнит-тесты модулей проверяют модуль в одиночку (`tools/check_modules.sh`). Общие тесты — стыки:

| Набор | Что проверяет |
|---|---|
| EventSystem + ECSSystem | удар по погибшей сущности не попадает в нового владельца её слота (поколения); граф контрактов упорядочен; сущности из событий видны выборкам в следующем тике |
| JobSystem + MemorySystem + ECSSystem + EventSystem | параллельная система над пулом ECS (арены потоков, `ChunkBuffers`) даёт побитово одинаковые компоненты и события при 0, 1 и 7 потоках; `Pool` + `parallel_reduce` |
| MemorySystem + EventSystem | данные в `DoubleArena`, на которые ссылается событие, живы ровно тот тик, когда событие видно, затем — нули |
| CardDuel + JobSystem + MemorySystem + EventSystem | партия ИИ против ИИ: инварианты после каждого действия, одинаковая партия при любом числе потоков, журнал через шину по порядку, ZII-партия в арене, правила боя |
| WindowSystem + RendererSystem `[gpu]` | куб там, куда его проецирует Camera3D; глубина и отсечение; освещение солнцем и точечным светом; текст → Framebuffer → 3D-карта не перевёрнут; PNG туда-обратно; своя раскладка вершины |
| Core + все модули `[gpu]` | порядок хуков App; внедрённые клавиша и клик доходят до шины; память тика; JobSystem; шрифт; скриншот |

Метки CTest: `integration` и `integration-gpu` (doctest не передаёт список меток — одно значение;
метки CTest — регулярные выражения, поэтому `-L integration` берёт оба, а `-LE gpu` отбрасывает GPU).

```sh
ctest --test-dir build -L integration              # все общие тесты
ctest --test-dir build -L integration -LE gpu      # без видеокарты
```

## 7. Цифры и проверки

| Проверка | Результат |
|---|---|
| Все тесты движка (`ctest`), Release, clang 22 | **319 / 319** (было 251) |
| RendererSystem отдельно (`check_modules.sh`) | 104 теста; все 7 модулей собираются и проходят сами по себе |
| CardDuel `--autoplay --fast --ticks 3000` при `--threads 0, 1, 2, 3, 7, 15` | одна контрольная сумма `fccc1696468ab3ae` |
| CardDuel `--input-bot` | 24 команды кликами мыши, 0 отклонено, партия доиграна |
| Сборка | без предупреждений (`-Wall -Wextra -Wpedantic -Wshadow`, модуль — ещё `-Wconversion`) |

Один из прогонов автоигры дал другую сумму и втрое больше решений ИИ (три партии подряд) — похоже на нажатие R
в видимом окне во время прогона; повторы при тех же аргументах совпадают. Для полностью автономных замеров
в будущем пригодится режим «без ввода ОС» (скрытое окно, `AppConfig::visible = false` уже есть).
